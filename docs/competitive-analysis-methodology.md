# 竞品分析 Agent 配置方法论（迭代实验记录）

> **目的**：通过"竞品分析报告"这一个场景的反复迭代，沉淀出"如何让 Agent 交付达到好评价"的可推广方法论。
>
> **方法**：每一轮跑真实 workflow → 看产出 → 评分 → 改配置（skill/KB/偏好/template/workflow）→ 再跑。
>
> **目标**：形成可复用的配置范式，推广到产品专家的其他任务、其他专业领域。

---

## 实验设置

- **场景**：竞品分析报告（competitive-analysis-workflow）
- **Agent**：product（主力 Agnes/agnes-2.0-flash）
- **评审**：main（Agnes/agnes-2.0-flash）
- **目标案例**：对比 Cursor 与 Windsurf（两个真实可查的 AI 代码编辑器）

---

## 评价指标体系（5 维 × 5 分）

每份产出按以下 5 维打分，每维 0-5 分，总分 25 分。

| 维度 | 0-1 分（差） | 2-3 分（中） | 4-5 分（好） |
|:----|:-----|:-----|:-----|
| **结构完整** | 章节缺失/占位 | 章节齐但内容薄 | 四章节齐 + 矩阵 + 来源表 |
| **数据可信** | 无来源/编造 | 部分有来源 | 每个量化数据有来源 + 来源表完整 |
| **洞察深度** | 罗列不分析 | 有对比但无洞察 | 有差异化洞察 + 战略含义 |
| **建议可执行** | 无建议/空泛 | 有建议但不可执行 | P0/P1 优先级 + 具体行动 |
| **维度覆盖** | 单维度 | 2-3 维度 | 用户体验+功能+定价+策略全覆盖 |

**及格线**：总分 ≥ 15/25（每维 ≥ 3）
**优秀线**：总分 ≥ 20/25（至少 3 维 ≥ 4）

## 迭代记录

### Round 0 — 基线（当前配置）

**配置快照**：
- skill: competitive-analysis-methodology（六步闭环，通用）
- template: competitive-analysis-product（4 章节 + 矩阵 + 4 维度约束）
- KB: 空
- 偏好: 空
- workflow: product 单步产出 → main 评审循环

**产出**：15KB，四章节齐全，5 个关键发现，来源标注完整

**评分**：无法通过 Gate（4 个失败：matrix_min_cols、source_inline_required ×2、process_artifact）

**问题诊断**：
1. `matrix_min_cols: 4` 太严——Agent 用标准 3 列格式（维度|竞品A|竞品B）被误拦
2. `source_inline_required` 窗口 60 字符太短——定价对比正文数字离句末来源标注超过 60 字符
3. `source_inline` 没排除定价序列行（`$20 → $40/user`）——这些数字在表格里有来源，正文复述不该再要求
4. process_artifact 在 Agent 没填 align.md/verify.log 时拦住——但这是过程产物，不该阻塞

**下一轮改进**：放宽 matrix_cols + 放宽 source 窗口 + 排除 $ 行

---

### Round 1 — 配置修复（Gate 误拦修正）

**配置变更**：
- `matrix_min_cols`: 4 → 3
- `_check_source_inline` 窗口：60 → 120 字符
- 新增：排除含 `$` 的定价序列行
- 新增：数字前后都检查来源（覆盖 `[来源1]2026年` 形态）

**产出**：21KB / 263 行，四章节齐全，5 个关键发现 + 策略建议表 + 信息缺口

**Gate 结果**：execute:1 从 4 失败降到 1 失败（3 处年份缺标注）

**评分**：

| 维度 | 分 | 说明 |
|:----|:--:|:----|
| 结构完整 | 5 | 四章节齐全 + 矩阵 + 来源表 |
| 数据可信 | 4 | 来源标注完整（URL），但 3 处年份缺标注 |
| 洞察深度 | 5 | 5 个关键发现都有洞察 + 战略含义 |
| 建议可执行 | 5 | P0/P1 优先级 + 具体行动 + 依据 |
| 维度覆盖 | 5 | 用户体验+功能+定价+策略全覆盖 |
| **总分** | **24/25** | 优秀（≥20 优秀线）|

**关键发现**：
- Agent 产出质量已经很高，不需要 KB/偏好注入就能产出工业级报告
- Gate 的硬约束（矩阵/维度/来源）有效驱动了结构化产出
- 剩余 3 处年份缺标注是"年份"这种特殊数字——可考虑排除年份

### Round 2 — submit_result 指引 + 排除年份

**配置变更**：
- prompt 提交步骤强化：明确"步骤1 write /tmp/result.json + 步骤2 bash submit_result"两步缺一不可
- `_check_source_inline` 排除纯年份（19XX/20XX）

**问题**：Agent 写了 /tmp/result.json 但没跑 submit_result.py（prompt 指引不够明确）

**未跑完**：被 dimension_coverage 误拦（"用户体验"在标题但标题行 <10 字符）

---

### Round 3 — dimension_coverage + source_inline 误拦修复 + KB/偏好注入

**配置变更**：
1. `dimension_coverage`：维度词出现在章节标题（## 开头）即算覆盖，不检查标题行长度
2. `source_inline`：排除 leading zero 数字（07月、1.07 版本号）
3. SKILL.md 重写：从"六步流程理论"改为"按交付物四章节写"的实操指引
4. KB 注入：沉淀"AI 代码编辑器竞品分析权威来源"（6 个 URL + 关键数据点）
5. 偏好库注入：创建"竞品分析报告风格"分节（5 条交付风格规则）

**结果**：execute:1 **首次即通过 Gate**（gate_passed），无需重试

**关键发现**：
- 配置 bug 修复后，Agent 一次产出就能通过 Gate
- SKILL.md 按章节写比按流程写更有效（Agent 直接照章节组织产出）
- KB 注入提供了权威来源，Agent 用的就是这些来源
- 偏好库塑造了交付风格（分析洞察列、P0/P1 优先级）

## 方法论雏形（基于 Round 0-3）

### 配置范式：四层驱动质量

通过 4 轮迭代，发现 Agent 交付质量由四层配置驱动，缺一不可：

| 层 | 作用 | 配置位置 | Round 验证 |
|:--|:-----|:---------|:----------|
| **L1 Gate 硬约束** | 拦结构缺陷（矩阵/维度/来源） | template.check_rules | Round 0→1：矩阵+来源约束让产出结构化 |
| **L2 SKILL 实操指引** | 告诉 Agent 每节写什么 | business/skills/*/SKILL.md | Round 3：按章节写比按流程写有效 |
| **L3 KB 知识注入** | 提供权威数据来源 | KB（source=user） | Round 3：注入来源后 Agent 直接用 |
| **L4 偏好库风格** | 塑造交付风格 | 偏好库分节 | Round 3：分析洞察列、P0/P1 优先级 |

### 关键教训

1. **Gate 约束要精确** — 太严会误拦合理产出（Round 0 的 matrix_cols=4、Round 2 的年份、Round 3 的标题行）
2. **SKILL 要按交付物组织** — 不是按"理论流程"，是按"每节写什么"
3. **KB 提供"半成品"** — 与其让 Agent 自己找来源，不如直接给它权威来源
4. **偏好库管"风格"** — 不是内容，是交付风格的统一

### 可推广范式

任何专业任务（不仅竞品分析）的配置四步：

```
1. 定义 task_type + delivery_template（章节 + check_rules）
2. 写 SKILL.md 按"交付物章节"组织实操指引
3. KB 沉淀该领域的权威来源/关键数据
4. 偏好库沉淀交付风格规则
```

推广到其他领域（审计/法律/医疗等）时，只需替换内容，配置范式不变。
