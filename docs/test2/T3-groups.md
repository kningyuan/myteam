### T3.4 消息重复问题（深度验证）

| 项 | 详情 |
|----|------|
| **操作** | 查看群聊消息流 + 后端API双重验证 |
| **预期** | 消息按时间排序，无重复 |
| **实际** | 记录级id去重已修复，但内容级重复未修复 |
| **结果** | ⚠️ 有 Bug（内容级重复未修复） |

**Bug 详情（2026-06-27 二次验证）**：

| 验证维度 | p_demo 群 | p_wf 群 |
|----------|-----------|---------|
| API 返回消息总数 | 50 | 47 |
| 唯一 id 数 | 50 | 47 |
| id 重复条数 | 0 | 0 |
| 唯一内容数 | 1 | 1 |
| **内容重复条数** | **49** | **46** |
| sender 分布 | research × 50 | research × 47 |

**验证结论**：
- **记录级（同 id）重复——已修复**：所有消息的 id 均唯一，无同一条记录被重复入库
- **内容级（同通知多次发送）重复——未修复**：同一条任务完成通知被反复推入群消息
  - p_demo 的 50 条消息内容完全相同，均为 research 发送的"📋 ✅ 任务完成 / 项目：p_demo / 任务：t1"
  - p_wf 的 47 条消息也只有 1 种内容
- **突发重复模式**：1-2 秒内会连续发出 3-6 条相同内容的通知（毫秒~秒级密集重复）

**根因分析**：
- 通知发送端（任务完成 → 群消息广播链路）没有按 `(group_id, task_id, 事件类型)` 做短时去重
- 任务完成事件被多个监听方重复捕获或事件本身被重复派发
- 建议在 `persist_group_message` / 通知发送处加幂等闸门（同一任务完成事件在 N 秒内只发一次）
