## 圆桌讨论流程预期

根据产品设计文档，圆桌讨论完整流程如下：

```
1. 发起讨论
   ├─ 主持人（main agent）发起议题
   ├─ 指定参与角色和人数
   └─ 设置讨论规则和时间限制

2. 独立思考阶段
   ├─ 各参与 Agent 独立分析议题
   ├─ 形成初步观点和论据
   └─ 互不干扰，确保观点多样性

3. 立论陈述阶段
   ├─ 各 Agent 依次陈述观点
   ├─ 提供证据和推理过程
   └─ 其他 Agent 可记录但不打断

4. 交叉质询阶段（可选）
   ├─ Agent 间可互相提问
   ├─ 深入探讨分歧点
   └─ 主持人引导讨论方向

5. 总结归纳阶段
   ├─ 主持人总结各方观点
   ├─ 提炼共识和分歧
   └─ 形成讨论纪要

6. 方案起草阶段
   ├─ 基于讨论结果起草方案
   ├─ 整合各方合理意见
   └─ 形成可执行的方案文档

7. 投票表决阶段
   ├─ 各 Agent 对方案投票
   ├─ 统计投票结果
   └─ 通过则进入执行，不通过则返回讨论
```

## 验证方法建议

### 完整验证需要的前置条件

1. **配置完善**：
   - 确认圆桌讨论配置参数完整
   - 配置参与角色和讨论规则
   - 设置合理的超时和重试策略

2. **测试场景**：
   - 场景 1：简单议题（3 人讨论，快速达成共识）
   - 场景 2：复杂议题（5+ 人讨论，多轮迭代）
   - 场景 3：分歧议题（观点冲突严重，需要多轮协商）

3. **验证指标**：
   - 讨论流程是否按阶段推进
   - 各 Agent 是否独立思考，观点多样性
   - 总结是否准确反映各方观点
   - 投票机制是否正常工作
   - 讨论结果是否可追溯和沉淀
