## 需求变更工作流

变更一条需求需经以下三步，缺一不可：

### 步骤一：改总表（本文件）

在 `docs/new/02-需求总表.md` 对应条目做以下更新：

- 修改 **描述** 或 **验收标准**，同步更新 **状态**。
- 若优先级变化，在本条注明原因（括号内写版本/日期）。
- 若新增需求，按 ID 命名规则（`R-<层>-<序号>`）追加到对应组，同步更新统计表。

### 步骤二：写实现说明

在 `docs/new/impl/<需求ID>/IMPL.md` 创建实现说明（模板见 [04-单需求实现模板.md](./04-单需求实现模板.md)），包含：

1. **变更动机**：为什么改？关联 ADR 或 decision 编号。
2. **影响分析**：改哪些文件？会影响哪些现有测试？
3. **实现步骤**：拆解为可独立验证的子步骤（含目标文件路径）。
4. **回归范围**：需要重跑哪些测试 / 回归脚本。

### 步骤三：回归验证

完成实现后，按以下顺序验证：

```bash
# 1. 单测（变更直接关联的模块）
PYTHONPATH=backend venv/bin/python3 -m pytest backend/common/tests/test_<module>.py -q

# 2. 全量单测（确保无 regression）
PYTHONPATH=backend venv/bin/python3 -m pytest backend -q

# 3. 对应回归脚本（若需求有关联 reg_*.py）
export MYTEAM_ROOT="$PWD" PYTHONPATH="$PWD/backend" NO_PROXY="localhost,127.0.0.1,::1"
venv/bin/python3 scripts/regression/reg_<关联脚本>.py

# 4. 更新需求总表状态为「已完成」，并在验收标准列标注通过的测试名称
```

验证通过后，将 `docs/new/02-需求总表.md` 对应条目的 **状态** 改为「已完成」，并在 commit message 中引用需求 ID（如 `fix(kernel): R-K13 recurring 调度实现`）。
