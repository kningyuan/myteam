## 一、快速入门

### 1.1 产品概述

**myteam 是一个工业级多 Agent 协作框架**，为团队提供从"单 Agent 交互式执行"到"多 Agent 结构化编排"的全链路协作能力。

它不是一个 AI 助手，而是一个**协作操作系统**——让多个 AI Agent 像一个团队一样，有分工、有流程、有质量门禁、有迭代改进，最终可靠地交付复杂任务。

**三大核心能力域：**

| 能力域 | 说明 | 典型场景 |
|--------|------|---------|
| **交互式执行** | 与单个 Agent 私聊，快速完成任务 | 代码开发、文案撰写、快速调研 |
| **编排式交付** | 通过 Workflow 定义流程，多 Agent 协作交付 | PRD 撰写、产品调研、复杂项目开发 |
| **知识与经验沉淀** | 任务经验自动沉淀，越用越聪明 | 团队知识库、最佳实践、质量画像 |

### 1.2 界面导航

myteam 采用 Discord 风格的三栏布局：

```
┌──────┬──────────┬──────────────────────┐
│ 主导航│  列表/搜索 │    详情/内容主区       │
│ Rail │  第二列   │    第三列             │
│      │          │                      │
│ 🏠   │          │                      │
│ 💬   │  Agent   │   对话内容            │
│ 👥   │  列表    │                      │
│ 📁   │          │                      │
│ ⚡   │          │                      │
│ 🗂️   │          │                      │
│ 🔀   │          │                      │

| 🔌   │          │                      │

```

**主导航（左侧竖排图标栏，从上到下）：**

| 图标 | 名称 | 路径 | 功能说明 |
|------|------|------|---------|

### 1.3 首次使用指引

**第一次使用 myteam，建议按以下顺序操作：**

```
Step 1：初始化团队
  └─ 进入「管理 → Agent」，确认 Agent 角色已配置
  └─ 进入「管理 → 偏好库」，设置团队偏好

Step 2：快速体验
  └─ 进入「对话」，选择一个 Agent 开始私聊
  └─ 感受单 Agent 的执行能力

Step 3：进阶使用
  └─ 进入「项目」，创建第一个 Workflow 项目
  └─ 观察多 Agent 协作过程
  └─ 查看交付物和成本

Step 4：深度使用
  └─ 进入「流程」，自定义工作流
  └─ 进入「管理 → 任务类型」，扩展任务类型
  └─ 进入「Skill」，安装领域 Skill
```

## 二、Agent 私聊（交互式执行）

### 2.1 功能说明

用户可以与单个 Agent 进行自然语言对话，Agent 可以在对话中直接执行任务——读写文件、运行命令、联网调研、使用 Skill 和 MCP 工具。

这是最灵活的使用方式，适合：
- 快速原型验证
- 探索性工作
- 简单一次性任务
- 需要人工实时干预的场景

### 2.2 操作步骤

**发起对话：**

1. 点击左侧主导航的「💬 对话」图标
2. 在第二列的 Agent 列表中选择一个 Agent
3. 第三列显示对话面板，在底部输入框输入消息
4. 按回车或点击发送按钮

**对话操作：**

| 操作 | 方法 | 说明 |
|------|------|------|
| 发送消息 | 输入框输入 + 回车 | 支持 Markdown 格式 |
| 查看思考过程 | 点击消息上的「思考」展开 | Agent 的内部推理过程 |
| 查看工具调用 | 点击消息中的工具卡片 | Agent 使用了哪些工具 |
| 清空对话 | 点击右上角「清空」按钮 | 清空当前对话历史 |
| 归档对话 | 点击右上角「归档」 | 对话移入归档，可恢复 |
| 搜索对话 | 第二列顶部搜索框 | 按名称搜索 Agent |

### 2.3 预期结果

- Agent 会理解你的自然语言指令
- Agent 可以使用工具（读文件、写文件、运行命令、联网搜索等）
- 回复以 Markdown 格式渲染，支持代码高亮
- 长任务支持流式输出，实时展示进度
- 刷新页面后对话继续，不中断

### 2.4 注意事项

- 每个 Agent 有独立的对话记忆，不同 Agent 之间不共享
- 对话记忆有滚动摘要机制，长对话不会无限增长
- Agent 行为受其身份配置（IDENTITY.md / SOUL.md）约束
- 挂载的 Skill 和 MCP 工具决定了 Agent 能做什么

## 三、群组协作

### 3.1 功能说明

群组是多 Agent 协作的空间，支持：
- **群聊模式**：@ 具体 Agent，多 Agent 并发响应
- **圆桌讨论模式**：多轮立论 → 主持汇总 → 对齐 → 投票 → 共识
- **项目协作群**：项目启动自动建群，实时同步进度

### 3.2 创建群组

**操作步骤：**

1. 点击左侧主导航的「👥 群组」图标
2. 在第二列顶部点击「+ 新建群组」
3. 填写群组名称和描述
4. 选择初始成员（可多选 Agent）
5. 点击「创建」

**预期结果：**
- 群组出现在列表中
- 所有选中的 Agent 自动加入
- 可以立即开始群聊

### 3.3 群聊与 @ 提及

**操作方式：**

1. 在群聊输入框中输入消息
2. 输入 `@` 会弹出 Agent 选择列表
3. 选择要 @ 的 Agent（可以 @ 多个）
4. 发送消息

**预期结果：**
- 被 @ 的 Agent 会收到通知并回复
- 多个被 @ 的 Agent 并发响应
- 消息流实时更新，支持流式输出
- 可以看到每个 Agent 的已读回执

### 3.4 圆桌讨论模式

> 适合需要多 Agent 充分讨论、达成共识的场景，如技术方案评审、需求对齐、决策讨论。

**触发方式：**

在群聊中输入 `@all 圆桌讨论：[议题]` 或使用群设置中的「发起圆桌」按钮。

**讨论流程（6 阶段状态机）：**

```
独立思考 → 立论 → 主持汇总 → 对齐 → 草案 → 投票
   │         │        │         │       │       │
   └─────────┴────────┴─────────┴───────┴───────┘
                多轮循环，直到达成共识
```

**各阶段说明：**

| 阶段 | 说明 | 参与者动作 |
|------|------|-----------|
| **独立思考** | 每个 Agent 独立思考议题，不看别人的意见 | 各自输出初始观点 |
| **立论** | 公开发表各自的论点和依据 | 每人陈述立场和理由 |
| **主持汇总** | 主持人汇总各方观点，整理分歧点 | 主持人输出总结 |
| **对齐** | 针对分歧点进行讨论，互相回应 | 补充/反驳/调整观点 |
| **草案** | 基于讨论输出共识草案 | 主持人起草结论 |
| **投票** | 所有参与者投票表决 | 赞成/反对/弃权 |

**圆桌设置项（在成员管理中配置）：**

| 设置项 | 说明 | 默认值 |
|--------|------|--------|
| 最大讨论轮数 | 最多多少轮讨论 | 可配置 |
| 参与率阈值 | 多少比例成员参与才算有效 | 可配置 |
| 单轮超时 | 每轮最长等待时间 | 可配置 |
| 主持人 | 谁来主持讨论 | 默认 main |

### 3.5 成员管理

**操作入口：** 群组详情页右上角「成员管理」按钮

**可执行的操作：**

| 操作 | 说明 |
|------|------|
| 添加成员 | 从 Agent 列表中选择添加到群组 |
| 移除成员 | 将 Agent 移出群组 |
| 调整发言顺序 | 圆桌讨论时的发言顺序 |
| 设置主持人 | 指定谁来主持圆桌讨论 |
| 设置最大轮数 | 圆桌讨论的最大轮次 |
| 解散群组 | 删除群组（可恢复已解散群组） |

## 四、项目编排（Workflow 执行）

### 4.1 功能说明

用户可以定义或选择一个 Workflow，启动一个项目。框架自动按照 Workflow 定义的 DAG（有向无环图）调度多个 Agent 协作完成任务，每个任务都有形式化 Gate 门禁和可选的同行评审，任务可以动态拆分子任务，可以用 Loop 机制迭代改进，最终交付经过质量保证的产出物。

这是最可靠的使用方式，适合：
- 标准化、重复性高的任务
- 需要多角色协作的复杂任务
- 对交付质量有明确要求的任务
- 需要可审计、可追溯的任务

### 4.2 创建项目

**操作步骤：**

1. 点击左侧主导航的「📁 项目」图标
2. 在第二列顶部点击「+ 新建项目」
3. 填写项目配置：

| 配置项 | 说明 | 必填 |
|--------|------|------|
| 项目目标 | 用自然语言描述要完成的目标 | ✅ |
| 工作流选择 | 选择一个预设的 Workflow，或使用自动推导 | ✅ |
| 模式 | one_shot（单次）/ recurring（周期性） | ✅ |
| Token 预算 | 项目最多消耗多少 Token | ✅ |
| 同行评审 | 是否启用 Peer Review | 可选 |
| 自动拆分 | 是否允许任务动态拆分子任务 | 可选 |
| 最大周期 | 最多执行多少个周期 | 可选 |

4. 点击「创建并启动」

**预期结果：**
- 项目出现在列表中，状态为「运行中」
- 自动开始 team_config 阶段（组建团队）
- 可以在详情页实时查看进度

### 4.3 项目总览页

进入项目详情后，默认显示「总览」Tab，包含：

| 模块 | 说明 |
|------|------|
| **启动配置** | 项目目标、所选 Workflow、运行选项 |
| **运行选项** | 是否启用 review、split、parallel 等 |
| **周期进度** | 当前执行到第几个周期、总周期数 |
| **成本概览** | 已消耗 Token、预算剩余、预计总消耗 |
| **状态徽章** | pending / in_progress / paused / completed / failed |

### 4.4 DAG 任务视图

点击「DAG」Tab 查看任务依赖图：

- 每个节点代表一个任务
- 箭头表示依赖关系（上游完成才能开始下游）
- 节点颜色表示状态（待执行/执行中/已完成/失败/评审中）
- 鼠标悬停查看任务详情（负责人、耗时、状态）

**任务状态说明：**

| 状态 | 颜色 | 说明 |
|------|------|------|
| pending | 灰色 | 等待依赖任务完成 |
| in_progress | 蓝色 | Agent 正在执行 |
| needs_review | 橙色 | 等待同行评审 |
| completed | 绿色 | 已完成 |
| failed | 红色 | 失败（可能进入 triage） |
| paused | 黄色 | 暂停 |

### 4.5 执行详情

点击「执行」Tab 查看详细执行过程：

| 模块 | 说明 |
|------|------|
| **执行树** | 任务的层级结构（父任务 → 子任务） |
| **迭代进度卡** | Loop 循环的轮次进度 |
| **任务质量卡** | 每个任务的质量指标（Gate 结果、自评、评审） |
| **Gate 失败列表** | Gate 门禁未通过的任务及失败原因 |

**点击单个任务**可以进入 Execute 详情页，查看：
- Prompt：发给 Agent 的完整提示词
- Harness：执行框架代码
- Deliverable：任务交付物内容
- Ledger：任务经验账本

### 4.6 交付物查看

点击「交付物」Tab 查看项目产出：

- 按任务组织的交付物列表
- 支持在线预览 Markdown 格式
- 可下载原始文件
- 每个交付物标注任务来源和质量评分

### 4.7 成本分析

点击「成本」Tab 查看 Token 消耗：

| 维度 | 说明 |
|------|------|
| **总消耗** | 项目累计 Token 消耗 |
| **按 Agent 分布** | 每个 Agent 消耗的 Token 占比 |
| **按任务分布** | 每个任务消耗的 Token |
| **预算进度** | 已用预算 / 总预算 |
| **预估剩余** | 按当前速率估算还需多少 Token |

## 五、工作流管理

### 5.1 功能说明

工作流（Workflow）定义了项目的任务编排方式——有哪些任务、谁来做、依赖关系是什么、是否有循环迭代。通过可视化编辑器，可以自定义复杂的协作流程。

### 5.2 创建工作流

**操作步骤：**

1. 点击左侧主导航的「🔀 流程」图标
2. 点击「+ 新建工作流」
3. 填写基本信息（名称、描述）
4. 进入编辑器添加步骤

### 5.3 步骤编辑器

在工作流编辑器中，可以：

- **添加步骤**：点击「+ 添加步骤」，配置步骤的任务类型、负责人
- **设置依赖**：勾选该步骤依赖哪些前置步骤
- **配置任务类型**：选择该步骤执行什么类型的任务
- **指定角色**：由哪个角色的 Agent 来执行

### 5.4 循环配置

工作流支持 Loop 循环机制，用于需要迭代改进的场景：

**配置项：**

| 配置项 | 说明 |
|--------|------|
| 循环类型 | v1（until 条件循环）/ v2（多 body 分支） |
| 退出条件 | 满足什么条件时退出循环（如 review_passed） |
| 最小轮数 | 至少迭代多少轮 |
| 最大轮数 | 最多迭代多少轮（防止死循环） |
| PATCH 模式 | 后续轮次基于上一轮交付物修改，不全文重写 |

### 5.5 过渡与分支

v2 格式支持多个 body 分支和 transition 跳转：

- 定义多个 body（不同的任务组合）
- 定义过渡条件（assess 结果满足什么条件时跳转到哪个 body）
- 实现类似「质量差 → 补强 → 再评审」的分支逻辑

## 六、管理中心

管理中心是团队配置的核心，包含 6 个子模块。

> 入口：左侧主导航「🗂️ 管理」，顶部 Tab 切换

### 6.1 Agent 管理

管理团队中的所有 AI Agent 角色。

**操作功能：**

| 功能 | 说明 |
|------|------|
| 新建 Agent | 添加新的 Agent 角色 |
| 编辑 Agent | 修改 Agent 的配置 |
| 删除 Agent | 移除 Agent 角色 |
| 后端配置 | 选择使用哪个 CLI 后端（opencode / claude / Codex） |
| 模型配置 | 选择默认模型 |
| Skill 挂载 | 为 Agent 挂载 Skill 包 |
| MCP 挂载 | 为 Agent 挂载 MCP 工具 |
| 身份文件编辑 | 直接编辑 IDENTITY.md / SOUL.md / AGENTS.md |
| Skill 同步 | 同步最新的 Skill 配置 |
| MCP 同步 | 同步最新的 MCP 配置 |

**Agent 身份文件说明：**

| 文件 | 作用 |
|------|------|
| IDENTITY.md | 角色身份、定位、能力边界 |
| SOUL.md | 性格、价值观、行为风格 |
| AGENTS.md | 团队协作规则、其他角色认知 |
| MEMORY.md | 个人记忆（自动维护） |

### 6.2 偏好库

管理团队的全局偏好设置，所有 Agent 都会参考这些偏好。

**功能说明：**

- 团队偏好全员共享
- 按分节组织（style / avoid / principles / tools 等）
- 修改后自动同步到所有 Agent
- 有界注入（字符上限，防止 prompt 膨胀）

**操作：**
- 直接在编辑器中修改偏好内容
- 点击「保存」后生效
- 下次对话/任务中自动体现

### 6.3 知识库

管理团队的长期知识库（L3 记忆），存储团队知识、最佳实践、历史经验。

**功能说明：**

- 结构化条目，支持按 task_type 模板分节
- Tag 分类 + 全文检索
- 按 project_id / task_type 过滤
- 任务成功后自动写入 Ledger 经验

**操作：**

| 操作 | 说明 |
|------|------|
| 新建条目 | 手动添加知识条目 |
| 编辑条目 | 修改条目内容 |
| 删除条目 | 移除知识条目 |
| 标签管理 | 管理分类标签 |
| 筛选视图 | 全部 / 团队通用 / 按项目 / L1 工作记忆 |

### 6.4 任务类型

管理系统支持的任务类型，定义了每种任务的交付格式、验收标准、检查规则。

**功能说明：**

- 每种任务类型对应一套 Gate 检查规则
- 定义交付物的产出形态（markdown / code_project 等）
- 配置验收标准（acceptance_criteria）
- 支持 AI 推导（自动推断任务类型）

**配置项：**

| 配置项 | 说明 |
|--------|------|
| 任务类型名称 | 唯一标识 |
| 产出形态 | markdown / code_project / action 等 |
| Gate 算法 | 使用哪些门禁检查规则 |
| 交付要求 | 交付物的章节结构要求 |
| 章节结构 | must_include / should_include 等 |
| 严格模式 | 是否启用强校验 |

### 6.5 交付模板

管理各类交付物的完整模板和章节结构。

**功能说明：**

- 每种交付物类型有对应的模板
- 任务开始时自动脚手架生成模板
- Agent 在模板基础上填充内容
- 支持 YAML 格式编辑

**操作：**
- 新建/导入模板
- 编辑 YAML 内容
- 绑定任务类型
- 配置章节设置

### 6.6 交付流程

管理 Delivery Profile（交付套餐），定义项目执行过程中产生哪些过程产物。

**配置项：**

| 配置项 | 说明 |
|--------|------|
| Profile 名称 | 套餐名称 |
| 过程产物 | process_artifacts（align / plan / verify 等） |
| 脚手架配置 | scaffold 配置（预生成哪些文件） |
| 绑定任务类型 | 适用于哪些任务类型 |

## 七、Skill 管理

### 7.1 功能说明

Skill 是 Agent 的"专业技能包"——包含特定领域的方法论、工具使用指南、最佳实践。通过挂载 Skill，Agent 可以获得特定领域的专业能力。

### 7.2 Skill 浏览与安装

**操作步骤：**

1. 点击左侧主导航的「✨ Skill」图标
2. 总览页以卡片网格展示所有 Skill
3. 点击某个 Skill 查看详情：
   - 文件树：Skill 包含哪些文件
   - 内容预览：SKILL.md 内容
   - 分类标签
4. 安装/卸载 Skill

### 7.3 分类管理

- Skill 按分类组织（如开发、产品、设计、研究等）
- 支持新建分类
- 支持 Skill 组（vendor 套件）批量挂载

### 7.4 待审批 Skill

> Skill 后台评审机制：任务完成后，系统会自动提取 Agent 总结的 Skill 改进建议，写入 _pending/ 目录等待人工审批。

**审批流程：**

1. 进入 Skill 页，切换到「待审批」视图
2. 查看待审批的 Skill patch（补丁）
3. 操作：
   - **批准**：patch 生效，Skill 更新
   - **拒绝**：丢弃该 patch
   - **修改后批准**：手动调整内容后批准

## 八、MCP 工具管理

### 8.1 功能说明

MCP（Model Context Protocol）是标准的工具集成协议，通过 MCP 可以让 Agent 使用外部工具服务（如数据库、API、文件系统等）。

### 8.2 添加 MCP 服务

**操作步骤：**

1. 点击左侧主导航的「🔌 MCP」图标
2. 点击「+ 新建 MCP Server」
3. 填写配置：

| 配置项 | 说明 |
|--------|------|
| 服务名称 | 唯一标识 |
| 命令 | 启动 MCP Server 的命令 |
| 参数 | 命令行参数 |
| 环境变量 | 所需的环境变量（如 API Key） |

4. 保存后自动连接测试

### 8.3 启用与停用

- 总览页卡片显示每个 MCP 服务的启用/停用状态
- 点击开关可快速启用/停用
- 启用后，挂载了该 MCP 的 Agent 才能使用对应的工具

## 十、核心业务流程指南

### 10.1 流程一：从零搭建团队

**适用场景**：第一次使用 myteam，需要从零配置团队。

**操作步骤：**

```
Step 1：配置 Agent 角色（管理 → Agent）
  ├─ 确认预置角色是否满足需求
  ├─ 如需新增，点击「新建 Agent」
  ├─ 配置每个角色的 IDENTITY.md（身份定位）
  └─ 配置后端和模型选择

Step 2：设置团队偏好（管理 → 偏好库）
  ├─ 填写团队风格偏好
  ├─ 填写禁忌/红线规则
  ├─ 填写工具偏好
  └─ 保存后自动同步到所有 Agent

Step 3：配置知识库（管理 → 知识库）
  ├─ 导入团队已有知识
  ├─ 设置分类标签
  └─ 配置知识模板

Step 4：安装领域 Skill（Skill 页）
  ├─ 浏览 Skill 库
  ├─ 安装需要的领域 Skill
  ├─ 挂载到对应 Agent
  └─ 配置 Skill 分类

Step 5：验证配置
  ├─ 进入对话页，与一个 Agent 私聊
  ├─ 测试 Agent 是否理解角色定位
  ├─ 测试 Agent 是否遵循偏好设置
  └─ 测试 Agent 是否能使用挂载的 Skill
```

**预期结果：**
- 团队有明确的角色分工
- 所有 Agent 遵循统一的团队偏好
- 知识库有初始内容
- Agent 具备领域专业能力

### 10.2 流程二：运行一个 Workflow 项目

**适用场景**：有一个明确的目标，需要多 Agent 协作完成，对交付质量有要求。

**操作步骤：**

```
Step 1：准备
  ├─ 确认已有合适的 Workflow
  │   └─ 没有的话先去「流程」页创建
  └─ 确认 Agent 角色已配置完成

Step 2：创建项目（项目页 → 新建项目）
  ├─ 填写项目目标（越具体越好）
  ├─ 选择 Workflow
  ├─ 设置 Token 预算
  ├─ 启用同行评审（高质量要求的项目）
  ├─ 启用自动拆分（复杂项目）
  └─ 点击「创建并启动」

Step 3：监控执行
  ├─ 总览页看整体进度
  ├─ DAG 页看任务依赖和状态
  ├─ 执行页看详细过程
  │   ├─ 看 Gate 检查结果
  │   ├─ 看评审意见
  │   └─ 看失败原因（如果有）
  └─ 成本页看 Token 消耗

Step 4：查看交付物
  ├─ 交付物 Tab 查看产出
  ├─ 在线预览或下载
  └─ 查看质量评分

Step 5：项目完成后
  ├─ 检查经验是否自动沉淀到知识库
  ├─ 查看 Agent 质量画像更新
  └─ 如有需要，手动调整 Workflow 配置
```

**预期结果：**
- 项目按 Workflow 定义的流程自动执行
- 每个任务经过 Gate 形式化检查
- 关键任务经过同行评审
- 交付物符合验收标准
- 经验自动沉淀到知识库
- 有完整的成本和质量记录

### 10.3 流程三：使用圆桌讨论做决策

**适用场景**：需要多个角色充分讨论、达成共识的决策场景。

**操作步骤：**

```
Step 1：创建讨论群组（群组页 → 新建群组）
  ├─ 添加需要参与的 Agent 角色
  ├─ 设置主持人
  └─ 设置最大讨论轮数

Step 2：发起圆桌讨论
  ├─ 在群聊中输入：@all 圆桌讨论：[讨论议题]
  │   例：@all 圆桌讨论：技术方案选型，选 A 方案还是 B 方案？
  └─ 或点击「发起圆桌」按钮，填写议题

Step 3：观察讨论过程
  ├─ 独立思考阶段：各 Agent 独立输出观点
  ├─ 立论阶段：各 Agent 公开发表理由
  ├─ 主持汇总：主持人整理各方观点和分歧
  ├─ 对齐阶段：针对分歧深入讨论
  ├─ 草案阶段：主持人输出共识草案
  └─ 投票阶段：各 Agent 投票表决

Step 4：查看结果
  ├─ 投票结果
  ├─ 最终共识文档
  └─ 讨论完整记录

Step 5：沉淀（可选）
  └─ 共识结论自动写入知识库（如启用）
```

**预期结果：**
- 所有参与者充分表达观点
- 主持人有效控场和总结
- 分歧点被充分讨论
- 最终有明确的投票结果
- 产出共识文档
- 讨论过程完整可追溯

### 10.4 流程四：沉淀团队知识与经验

**适用场景**：团队运行一段时间后，系统化地沉淀知识和最佳实践。

**自动沉淀（框架自动完成）：**

| 沉淀类型 | 触发时机 | 存储位置 |
|---------|---------|---------|
| Ledger 经验账本 | 任务成功后 | 知识库 references/ |
| Lesson 教训 | 任务重试后 | 知识库教训库 |
| Skill 改进建议 | 任务完成后 | Skill _pending/ 待审批 |
| 质量画像数据 | 每个任务完成后 | Agent 质量画像 |

**人工沉淀（团队主动维护）：**

```
Step 1：定期评审 Skill 待审批队列
  ├─ 进入 Skill → 待审批
  ├─ 审查自动提取的 Skill 改进建议
  ├─ 批准/拒绝/修改后批准
  └─ 批准后 Skill 自动更新

Step 2：整理知识库
  ├─ 进入管理 → 知识库
  ├─ 审查自动沉淀的 Ledger
  ├─ 补充团队通用知识
  ├─ 整理分类标签
  └─ 删除过时/错误内容

Step 3：回顾质量画像
  ├─ 查看各 Agent 的质量趋势
  ├─ 识别质量薄弱的任务类型
  └─ 针对性优化（调整 Skill / 调整 Prompt / 调整 Gate 规则）

Step 4：优化 Workflow
  ├─ 基于历史项目数据
  ├─ 调整任务拆分策略
  ├─ 调整评审配置
  └─ 优化循环条件
```

**预期结果：**
- 团队知识库持续增长
- Skill 持续进化，越用越好
- Agent 质量画像可追踪
- Workflow 持续优化
- 形成「执行 → 沉淀 → 优化」的正向循环

## 附录 A：常见问题 FAQ

**Q: Agent 对话为什么没有记忆之前说过的话？**
A: 每个 Agent 有独立的对话记忆。确保在同一个对话窗口中，且对话没有被清空或归档。长对话会有滚动摘要，关键信息不会丢失。

**Q: 项目卡住了怎么办？**
A: 可以在项目总览页查看当前状态。如果是 paused 状态（如预算耗尽），可以追加预算后恢复。如果是任务失败进入 triage，等待协调者处理。

**Q: Gate 总是不通过怎么办？**
A: Gate 不通过通常是因为交付物格式不符合要求。可以：
1. 查看 Gate 失败详情，了解具体哪里不合格
2. 调整交付模板，降低 must_include 要求
3. 增加重试次数，给 Agent 更多修复机会

**Q: 如何添加新的任务类型？**
A: 进入「管理 → 任务类型」，点击新建。需要配置产出形态、Gate 规则、章节结构等。建议从已有类型复制修改。

**Q: Skill 待审批是什么意思？**
A: 任务完成后，系统会自动提取 Agent 总结的 Skill 改进建议，写入待审批队列。需要人工审核后才会生效，避免质量不好的自动更新污染 Skill 库。

**Q: 可以在手机上使用吗？**
A: myteam 是 Web 应用，手机浏览器可以访问，但针对桌面端优化，移动端体验可能受限。

**Q: 数据存储在哪里？**
A: 所有数据存在本地 SQLite 数据库（business/tasks/state.db）和文件系统中。myteam 不向外部服务器上传数据。

**Q: 如何备份数据？**
A: 直接备份 `business/` 目录和 `config/` 目录即可。包含所有项目数据、配置、知识库内容。
