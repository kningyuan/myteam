## 一、L3 愿景（摘自 00-升级总路线图）

| 能力 | 说明 |
|------|------|
| Skill 抽提/回读 | 从成功 run 提炼 pattern，写入 `business/skills/` 并可被后续 agent 回读 |
| self-upgrade workflow | 框架对自身代码的 plan→execute→review 闭环（人确认合入） |
| Budget 自动降级 | token 达预算阈值时切换更轻 backend/model，而非仅 pause |
| Level-3 发版门禁 | 内容→发布→证据 URL（content-campaign） |

**不可跳层**：L1→L2→L3；L3 前不得承诺无人值守自升级、全自动小红书。

## 三、范围冻结

### Phase 0 做

- 定义 `self-upgrade` workflow：plan（requirements + 评审 + decision）→ execute（code-writing + skill 草案）→ review（code-review + acceptance + release decision）
- REG-L3 CHECK_ONLY：验 workflow 存在 + `templates.yaml` 含所需 `task_type`
- 在 `kernel_config.py` **仅文档** 预留 `budget_degrade_threshold` 等字段名

### Phase 0 不做（明确推迟）

| 项 | 原因 |
|----|------|
| `process_from_defaults` 读取 degrade 字段 | 需 L2 budget 硬停稳定后再接 |
| 自动写入 `business/skills/*.md` | 需 Skill Pack 契约与 Gate 专规 |
| REG-L3 全量 E2E（run_kernel） | 依赖 L2 并行 + 真实 dogfooding 环境 |
| content-campaign Level-3 发布 REG | 独立场景 REG，与 self-upgrade 分列 |
| 新增 `skill-extract` task_type | 暂用 `research` 占位，避免 Registry 膨胀 |
| `run_regression.sh` 接入 REG-L3 | L3 里程碑合入前再挂 suite |

## 四、workflow 任务链（self-upgrade.yaml）

```
upgrade-plan (requirements)
    → plan-review (architecture-review)
    → plan-decision (decision-record)  ← 开放 🔴=0
    → impl-upgrade (code-writing)
    → skill-extract (research)         ← Skill scaffold
    → code-review (code-review)
    → acceptance (acceptance-report)
    → release-decision (decision-record) ← 人确认合入
```

**roster**：`main`, `arch`, `qa`, `product`
