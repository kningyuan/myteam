# 标准协作模式总结 — 2026-06-09

> **结论**：myteam 已具备一套可复现、可走通的工业级协作「金路径」。  
> 成功标准：**项目 completed + 交付物落盘 + gate_passed**；`needs_review` 为质量标签，非失败。

---

## 1. 问题背景

早期体感「跑不通」主要来自：

| 现象 | 根因 |
|------|------|
| `timed_out` / `no_response` | live 规划步数多、main 扛重 strategy、描述弱、看门狗偏紧 |
| `gate_failed` | 未写 deliverable 或未 `submit_result` |
| 改设置「跳过 16 个 agent」 | UI backend 与 agent 实际 backend 不一致 |
| 改代码看不出进步 | 单测绿 ≠ 真实 CLI E2E；缺交付物保证与标准 prompt |

---

## 2. 标准模式架构

### 2.1 两条正交流

```
A) Hub 聊天：frontend → hub → agent_chat → adapter → SSE
B) 内核编排：run_kernel → Process → TaskPipeline → AgentPort → CLI
```

标准协作模式主要指 **B)**；Hub 可选旁路观测（`/api/obs/...`）。

### 2.2 三层职责（System / Strategy / Skill）

| 层 | 职责 | 本模式落点 |
|----|------|------------|
| **System Kernel** | 状态机、Gate、Store、看门狗、交付物 adopt | `deliverable_guarantee.py`、`task_pipeline.py`、`agent_port.py` |
| **Strategy Registry** | task_type、prompt 壳、workflow、验收格式 | `templates.yaml`、`prompt_templates.yaml`、`business/workflows/*.yaml` |
| **Skill Pack** | 单 agent 怎么做细 | `business/skills/*`、`workspace-*/AGENTS.md`（Cursor 侧另论） |

**硬边界**：prompt 按 **task_type** 标准化，**不按 agent** 写死；agent 只决定「谁执行」。

### 2.3 数据流（execute）

```
workflow.description（变量）
    + prompt_templates.yaml（task_type 标准壳）
    → render_execute_intent()
    → build_worker_prompt()（章节 + submit_result 约束）
    → CLI agent
    → submit_result → Gate → Store
```

决策类（`team_config` / `task_plan`）同理：`decision_pipeline` + `prompt_templates.yaml` 的 `kinds` 段。

## 3. 金路径配方

### 3.1 发起方式

**方式 A — 固定 workflow（推荐首发）**

```bash
export MYTEAM_ROOT="$PWD" PYTHONPATH="$PWD/backend"
venv/bin/python3 backend/common/run_kernel.py <project_id> \
  --workflow tier-l2-heavy \
  --goal "…" --title "…" \
  --budget 1000000 --backend claude
```

**方式 B — 自由规划（workflow 留空）**

```bash
venv/bin/python3 backend/common/run_kernel.py <project_id> \
  --goal "$(cat business/workflows/tier-l3-free-goal.txt)" \
  --budget 1000000 --backend claude
```

### 3.2 推荐 workflow

| ID | 步数 | 用途 |
|----|------|------|
| `prompt-matrix-smoke` | 4 | 多 agent × 多 task_type 矩阵冒烟 |
| `tier-l2-parallel` | 4 | 三并行 research + strategy（轻） |
| `tier-l2-heavy` | 5 | 三并行 research + requirements + strategy（加重） |

### 3.3 description 写法（只写变量）

```text
【对象】https://github.com/iOfficeAI/AionUi
【视角】产品：定位、用户、场景
【范围】仅 README、docs/、Releases
【输入】只读 t-xxx 交付物        # 汇总/依赖步
```

**禁止**在 description 重复：章节标题、篇幅、交卷步骤、禁止全仓扫描等——这些在 `prompt_templates.yaml`。

### 3.4 默认运行参数

| 项 | 推荐值 | 配置位置 |
|----|--------|----------|
| token 预算 | `1000000` | CLI `--budget` |
| soft_idle | `240s` | `config/skill_config.json` → `process_defaults` |
| hard_idle | `900s` | 同上 |
| max_gate_retries | `5` | 同上 |
| 步数 | 4–6 | workflow / task_plan goal |
| task_type 权重 | research → requirements → strategy | workflow 设计 |

### 3.5 成功判定（工业第一档）

- ✅ `project.status == completed`
- ✅ 每步有 `business/tasks/project/<id>/deliverables/*`
- ✅ `run_event` 中 `gate_passed`，无 `gate_failed`
- ⚠️ `needs_review`：自评 `known_gaps` 非空或 `score < 0.6`，**不阻塞下游**（默认）

## 5. 关键代码锚点

| 模块 | 路径 | 作用 |
|------|------|------|
| Prompt 渲染 | `backend/common/prompt_templates.py` | task_type / kind 模板合并 |
| 模板源 | `business/templates/prompt_templates.yaml` | 标准壳（Strategy） |

| 决策流水线 | `backend/common/decision_pipeline.py` | team_config / task_plan 模板 |
| 交付物保证 | `backend/common/deliverable_guarantee.py` | 骨架预写 + adopt |
| Worker 提示 | `backend/common/agent_transport.py` | 章节示例 + submit_result |

## 6. 已知边界与反模式

| 反模式 | 后果 |
|--------|------|
| main 长 live strategy、弱描述 | `timed_out` |
| description 塞满格式条款 | 与模板重复、规划漂移 |
| 把 needs_review 当失败 | 误判「没跑通」 |
| 单测全绿就当 E2E 稳 | mock 不覆盖 CLI 交卷行为 |
| workflow roster 含未注册 agent | 启动即失败 |
| agent 无 task_type 能力（如 arch→research） | 运行时校验失败 |

## 7. 本模式下 myteam 是否还需修正？

### 7.1 不必改（已满足金路径）

- execute 全任务同路径（`TaskPipeline.run_task`）
- task_type 标准 prompt 已接入内核
- 交付物保证层已接入
- 看门狗 / gate 重试 / 预算参数已上调并验证
- workflow 可选；自由规划可跑 5 步

**结论：按本模式日常使用，内核不必再大改。**

### 7.2 建议修正（P1，不挡封板）

| 优先级 | 项 | 说明 |
|--------|-----|------|
| P1 | **UI 语义** | 区分 `completed` / `needs_review` / `failed` 展示，避免用户误判 |
| P1 | **Hub 默认 goal 示例** | 新项目粘贴 `tier-l3-free-goal.txt` 级约束 |
| P1 | **补全 prompt 模板** | `content`、`architecture-review` 等 task_type 细化壳 |
| P1 | **黄金回归固化** | `tier_e2e` + `prompt_matrix_e2e` 发版前必跑（需真实 claude，慢） |
| P2 | **plan_gate 角色约束** | 自由规划时 strategy 偶发派给非 main（如 product），可加软校验 |
| P2 | **Hub 拆分** | `server.py` 单体过大，与协作闭环无直接关系 |
| P2 | **quality_floor / known_gaps 策略** | 若要求 UI 全绿 completed，调自评规则或 prompt |

### 7.3 暂不建议

- 为大而全重构 Process / AgentPort
- 在 service 层引入 CLI 专有逻辑（违反 adapter 隔离）
- 恢复 JSON rescue 路径
