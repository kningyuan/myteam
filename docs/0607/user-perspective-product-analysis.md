## 1. 执行摘要

站在**普通用户**（不是开发者）的角度，myteam 目前可以概括成一句话：

**「内核很强、能跑起来，但产品闭环还没做完——更像高级用户的本地编排控制台，还不是开箱即用的协作产品。」**

| 维度 | 用户感受 | 评分（主观） |
|------|----------|:------------:|
| 视觉与主题 | 暗色毛玻璃质感不错，不像粗糙内部工具 | ★★★★☆ |
| 上手难度 | 仍偏 CLI + 配置，Hub 不能独立完成全流程 | ★★☆☆☆ |
| 日常聊天 | 单聊/群聊可用，流式体验尚可 | ★★★☆☆ |
| 项目编排 | 后台能跑，但「看得见、管得住」不够 | ★★★☆☆ |
| 交付物 | 有浏览入口，体验和闭环仍弱 | ★★☆☆☆ |
| 出错自助 | CLI 有改善，Hub 里仍偏技术 | ★★☆☆☆ |

**优势**：多 Agent 编排、门禁、可观测、聊天/群组/Agent 管理都在一个 Hub 里，方向对。

**短板**：**「跑项目」和「用 Hub」仍是两条路**，用户容易在中间断档。

## 2. 现有功能：用户觉得怎么样

### 2.1 Home 仪表盘

- 有项目数、运行中、Token、成本等卡片。
- **问题**：数字静态、无趋势；首次使用空态无引导（不知道下一步该 `--init`、`--demo` 还是建项目）。
- **用户心声**：「我打开 Hub 了，然后呢？」

### 2.2 Chat（单 Agent 对话）

- 流式输出、thinking 折叠、主题切换都可用。
- **问题**：消息层级不够清晰；长对话可能卡；看不到本轮 token/耗时；和「项目执行」是割裂的。
- **用户心声**：「聊天能用，但不知道这和跑项目有什么关系。」

### 2.3 Groups（群组）

- 支持 @mention 分配 agent。
- **问题**：无 @ 补全下拉；群聊和单聊视觉太像；配置入口深。
- **用户心声**：「@ 谁要靠记 agent 名字，不像 Slack/Discord。」

### 2.4 Projects（可观测 / 编排）

这是**最重、也是卖点最多**的模块：Overview、Execution、Deliverables、Cost。

- **问题**：
  - **没有 DAG 图**——协作引擎核心卖点，用户只能看列表；
  - 执行树层级深时可读性差；
  - SSE 更新无「有新事件」提示；
  - 成本只有表格，缺图表；
  - 交付物只读预览，不能编辑/对比/下载体验弱。
- **用户心声**：「项目在跑，但我看不清全貌；失败了不知道改哪。」

### 2.5 Agents 管理

- 能看 agent 列表、改配置、看 task_type 注册表。
- **问题**：表格列太多要横滚；内联编辑易误触、无明确保存/取消。
- **用户心声**：「像后台管理，不像给业务用户用的。」

### 2.6 Settings

- 后端、模型等配置入口有。
- **问题**：信息密度不均；和 CLI 配置（opencode/claude 登录）关系不清晰。
- **用户心声**：「Hub 里配好了，终端还报错——不知道缺哪一步。」

### 2.7 CLI 编排（run_kernel）

- `--init`、`--demo`、用户文档（quick-start 等）已缓解新用户痛点。
- **问题**：多数用户期望 **在 Hub 里一键建项目、填 goal、看进度**；现在仍要终端。
- **用户心声**：「文档说 5 分钟跑通，但我得开两个窗口。」

## 3. 还缺什么（用户视角的功能缺口）

按优先级排列：

### P0 — 没有就难当「产品」

1. **Hub 内创建/启动项目**  
   填 goal → 选模式/预算 → 启动 → 看进度，不必切终端。
2. **统一 Workspace 时间线**  
   Chat、项目事件、任务状态、交付物进一条时间轴，而不是多 tab 各拉各的。
3. **DAG 可视化**  
   任务依赖、状态着色、点击进详情——这是和普通 ChatBot 的差异点。
4. **失败可行动**  
   失败/task blocked 时：原因（人话）+ 建议（重试/改配置/看日志）+ 一键跳转。
5. **首次使用引导（Onboarding）**  
   检测未 init → 引导 init/demo → 示例项目 → 第一次交付物。

### P1 — 日常用起来顺

6. **交付物完整闭环**：预览、下载、版本/对比、标记「最终交付」。
7. **项目列表增强**：筛选、搜索、状态徽章、最近活动。
8. **成本可视化**：按 agent/task 的柱状图/饼图，预算告警。
9. **群聊 @mention 补全** + 发言人标识。
10. **通知/订阅**：项目完成、失败、triage 需要人工——浏览器通知或 Hub 角标。

### P2 — 走向「可分享、可部署」

11. **鉴权**（哪怕简单 token/本地密码）——当前 `0.0.0.0` 无认证，局域网也不安心。
12. **多项目管理**：归档、模板、从 demo 复制。
13. **Skill / task_type 可视化配置**（不必手改 yaml/json）。
14. **导出/分享**：报告 PDF、运行摘要链接。

## 4. 现有功能该怎么提升

| 功能 | 现状 | 建议提升 |
|------|------|----------|
| 新用户路径 | CLI `--demo` 可用 | Hub 首页「一键 Demo」+ 空态引导 |
| 错误信息 | run_kernel 有人话提示 | Hub/API 统一错误码 + 排查链接 |
| 进度可视 | 有 Obs API + 项目页 | DAG 图 + 进度条 + 实时高亮 |
| 交付物 | 文件树 + 只读预览 | Markdown 渲染、diff、下载包 |
| Agent 管理 | 表格内联编辑 | 卡片/抽屉编辑 + 保存确认 |
| 聊天记忆 | DM 已有 memory 路径 | 显示上下文用量、清空/摘要 |
| 文档 | 6 篇用户文档已有 | Hub 内嵌帮助、术语悬浮解释 |

## 5. 页面/UI 具体该改什么

从用户感受收束成 **6 条最高 ROI** 的 UI 改进：

1. **信息架构**：Projects 拆二级导航（概览 / DAG / 执行 / 交付 / 成本），加面包屑。
2. **Home 空态**：插图 +「运行 Demo / 创建项目 / 初始化 Agent」三按钮。
3. **Projects：DAG 组件**（Canvas/SVG），节点可点、状态可筛。
4. **Chat/Groups**：三栏消息（头像+时间+内容）、@ 下拉、轮次分割线。
5. **实时反馈**：SSE 新事件 2s 高亮；运行中 tab 显示 pulse 指示。
6. **Agent 表**：列可隐藏、编辑改抽屉+确认，小屏不横滚。

视觉层面：暗色已好；**亮色模式层次感**、**组件一致性**（按钮/卡片/圆角统一）还可再 polish。

更详细的 UI 审计见 [`ui-design-assessment-and-upgrade-plan.md`](./ui-design-assessment-and-upgrade-plan.md)。

## 6. 和同类产品的用户预期差距

用户若用过 **Cursor / ChatGPT / Slack + Bot**，会期待：

| 用户预期 | myteam 现状 |
|----------|-------------|
| 开箱即用 | 仍要配 CLI、workspace、registry |
| 一个界面搞定 | Hub + 终端双轨 |
| 图形化进度 | 以列表为主 |
| 失败能自助 | 仍偏开发者日志 |

myteam 的差异化在 **确定性编排 + 多 Agent 分工 + Gate**，但**用户还感受不到**，因为可视化与闭环没跟上内核能力。

## 7. 结论与建议路线

### 7.1 现在怎么样？

- 对**会配环境、能跑终端的技术用户**：已经能聊天、看项目、管 Agent，**可用但偏工具感**。
- 对**产品/业务用户**：**门槛高、闭环断、卖点（DAG/协作）看不见**，容易在第一次就放弃。

### 7.2 若只选 3 件事让用户感知「这是产品了」

1. Hub 内 **创建并启动项目**（含 Demo）
2. **DAG + 统一时间线**（把编排卖点亮出来）
3. **失败人话 + 交付物闭环**（跑完能拿、挂了能修）
