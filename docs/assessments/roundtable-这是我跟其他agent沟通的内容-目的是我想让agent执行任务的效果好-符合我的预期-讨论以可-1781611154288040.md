⏺ 你的方向是对的，但有一个关键的细节要补上，不然「建了库但 agent 不去查」这个坑你会再踩一次。

  你理解的核心是对的

  任务来了
    ↓
  agent 查阅知识层 ← 品味库 + 经验库
    ↓
  按规则执行
    ↓
  交付

  这个模型没毛病。本质上就是把「你脑子里想让 agent 知道的东西」持久化到一个地方，agent 执行时去取。

  但关键在于：agent 是怎么「查阅」的？

  你有三个选择，效果天差地别：

  方法 A：让 agent 自己决定要不要读 ⬅️ 你目前的做法，效果最差

  prompt 里写：「如有需要，请查阅 SKILL.md」
  agent 读了 → 但也可以选择不读
  Gate 不检查它读没读

  这是你现在的问题——agent 有选择权。它可能因为「这个任务我懂」就不去读，然后按自己的训练数据行事，跟你的想法错位。

  方法 B：框架自动注入（推荐）⬅️ 知识库用这个

  agent 收到 prompt 时，相关条目已经被注入进去了
  agent 不需要「决定去查」，它直接看到

  myteam 的 experience.py 已经在这么做了——每次 execute 交互，自动注入 3 条同类任务经验。agent 不用选择读不读，它直接就在上下文里。

  品味库也应该这样：对齐检查 agent 的 prompt 里直接注入 taste bank 条目，不是让 agent 自己去读文件。

  方法 C：agent 拥有查询工具 ⬅️ 大规模用这个

  agent 有一个 search_taste() 工具
  执行过程中随时可以查

  C 适合大规模知识库（100+ 条目），B 适合中等规模（20-50 条），A 适合你已经知道 agent 肯定会去读的场景（比如它的核心身份文件）。

  对你来说最实际的架构

                      ┌─ 知识层 ─────────────────────┐
                      │                               │
  你写一次 →  Taste Bank（品味，20-50 条）             │
                       ↓ 自动注入（全部注入，量不大）        │
                       ↓                               │
  agent 自动沉淀 →  Knowledge Base（经验，持续增长）    │
                       ↓ 自动注入（top 3，按 task_type）   │
                       ↓                               │
  agent 自动写 →  MEMORY.md（个人备忘录）              │
                       ↓ 自动加载（workspace 里有）       │
                      └───────────────────────────────┘

  Taste Bank  →  对齐检查 agent 读它（确保交付符合你的风格）
  Knowledge Base → 执行 agent 读它（复用历史经验，不从头来）
  MEMORY.md  →  agent 自己的持续记忆（跨任务上下文）

  关键区别：

  ┌────────────────┬────────────────────────┬──────────────────────────┬────────────────────────────────────┐
  │                │          谁写          │          谁来读          │              注入方式              │
  ├────────────────┼────────────────────────┼──────────────────────────┼────────────────────────────────────┤
  │ Taste Bank     │ 你（或从你的反馈提取） │ 对齐检查 agent           │ 一次性全部注入 prompt（50 条不多） │
  ├────────────────┼────────────────────────┼──────────────────────────┼────────────────────────────────────┤
  │ Knowledge Base │ agent 执行后自动沉淀   │ 下次同类任务的执行 agent │ 按 task_type 检索 top 3 注入       │
  ├────────────────┼────────────────────────┼──────────────────────────┼────────────────────────────────────┤
  │ MEMORY.md      │ agent 每次执行后更新   │ 同一个 agent 下次执行    │ workspace 文件，CLI 自动读取       │
  └────────────────┴────────────────────────┴──────────────────────────┴────────────────────────────────────┘

  所以你的理解是正确的，但要补充一个设计原则：

  ▎ 不要让 agent「决定」去不去查知识层。让框架替它把相关的知识放到它眼前。

  你现在代码里有的（experience.py 自动注 3 条）是好的。缺的是品味库的自动注入，以及 MEMORY.md 的自动读写。要我帮你把这两块补上吗？可以先改
  experience.py 让它同时写 MEMORY.md，再建 taste bank 的注入机制。
