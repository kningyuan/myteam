# 多轮评审（Multi-Round Review）

> 适用场景：同一交付物需经历多轮审查迭代（R1 → 修复 → R2 → ...）。

## 轮次职责

| 轮次 | 职责 | 产出 |
|------|------|------|
| R1 | 全量扫描，发现所有缺陷并按🔴🟡🟢分级 | PATCH-N 清单 + 整体结论 |
| R2 | 验证 R1 每项修复 + 结构视角二次扫描 | 逐项核验表 + 新增问题 + PASS/FAIL 结论 |
| skill_review | 后台复盘，决定是否沉淀教训到 skill 库 | action + notes |

## R2 执行规程

1. **读 R1 交付物** — 获取前一轮的所有 PATCH-N 问题和分级
2. **逐项核验** — 对每个问题检查修复状态，记录 已修/未修/部分
3. **二次扫描** — 用结构视角（连贯性/可信度/结论追溯性）看整体，找出 R1 未覆盖的新问题
4. **合并输出** — 核验状态 + 新问题分优先级，给出 PASS/FAIL 结论

## 红线

- R2 不能跳过 R1 核验直接做二次扫描
- 每项核验须有证据（「问题 PATCH-1: 行42 已修改，内容见第5段」）
- 新问题须标注 Round=R2 以便与前一轮区分
- PASS 结论须明示「无残留阻塞项」
