# 代码质量提升方法论

## 任务描述
对代码进行系统性质量提升，覆盖可读性、可测试性、可维护性、性能与安全五个维度，产出质量评估报告 + 重构建议 + 可运行测试。

## 质量评估模型（5维 × 4级）

| 维度 | L1（及格） | L2（良好） | L3（优秀） | L4（卓越） |
|------|-----------|-----------|-----------|-----------|
| **可读性** | 命名有意义 | 函数≤30行 | 无注释也能懂 | 自文档化代码 |
| **可测试性** | 有单元测试 | 覆盖率≥70% | 覆盖率≥90% + 集成测试 | 变异测试通过 |
| **可维护性** | 无重复代码 | 圈复杂度≤10 | 单一职责 | 开闭原则 |
| **性能** | 无明显瓶颈 | 有性能基线 | 有性能回归测试 | 持续优化 |
| **安全** | 无已知漏洞 | 输入校验 | 最小权限 | 安全审计通过 |

## 代码审查清单

### 结构层面
- [ ] 函数长度 ≤30 行（Python）/ ≤20 行（TypeScript）
- [ ] 圈复杂度 ≤10
- [ ] 嵌套深度 ≤3 层
- [ ] 参数数量 ≤4 个（超过用对象封装）
- [ ] 文件长度 ≤300 行

### 命名层面
- [ ] 变量名是名词，函数名是动词
- [ ] 布尔变量用 is/has/can/should 前缀
- [ ] 避免缩写（`usr` → `user`，`btn` → `button`）
- [ ] 避免魔法数字（用常量命名）
- [ ] 避免通用名（`data`/`info`/`temp`/`util`）

### 逻辑层面
- [ ] 每个函数只做一件事（单一职责）
- [ ] 没有副作用（纯函数优先）
- [ ] 错误处理完整（不吞异常，不裸 except）
- [ ] 边界条件覆盖（空值/零值/极值/并发）
- [ ] 没有死代码（注释掉的代码直接删）

### 安全层面
- [ ] SQL 参数化查询（不用字符串拼接）
- [ ] 用户输入校验 + 转义
- [ ] 敏感信息不硬编码（用环境变量）
- [ ] 权限检查在入口处（不依赖前端）
- [ ] 日志不含敏感信息

## 重构模式

### 高优先级（先做）
1. **提取函数** — 长函数拆分为多个短函数，每个做一件事
2. **消除重复** — DRY 原则，提取公共逻辑到函数/基类
3. **命名优化** — 重命名所有模糊变量/函数
4. **消除魔法数字** — 提取为命名常量

### 中优先级
5. **简化条件** — 复杂 if-else → 策略模式 / 查表法 / 早返回
6. **提取类** — 上帝类拆分为多个职责单一的类
7. **引入参数对象** — 参数过多时封装为对象
8. **以多态替代条件** — type-switch → 子类覆写

### 低优先级（按需）
9. **函数组合替代继承** — 继承链深度 ≤2
10. **不可变数据** — 优先使用不可变结构

## 测试策略

### 测试金字塔
```
        E2E（5%）         — 关键用户路径
      集成测试（20%）      — 模块间交互
    单元测试（75%）        — 函数/类级别
```

### 测试编写原则
- **AAA 模式** — Arrange（准备）/ Act（执行）/ Assert（断言）
- **每个测试只验证一个行为** — 一个断言或一组相关断言
- **测试名描述行为** — `test_should_return_error_when_input_is_empty`
- **不测试实现细节** — 测行为不测实现，重构后测试不应失败
- **边界值必测** — 空值/零值/极值/null/undefined

### 测试覆盖目标
| 代码类型 | 行覆盖率 | 分支覆盖率 |
|----------|----------|------------|
| 核心业务逻辑 | ≥90% | ≥85% |
| 工具函数 | ≥95% | ≥90% |
| API 层 | ≥70% | ≥60% |
| UI 组件 | ≥50% | ≥40% |

## 性能优化清单

| 层面 | 检查项 | 工具 |
|------|--------|------|
| 数据库 | 慢查询、N+1、缺索引 | EXPLAIN / pt-query-digest |
| 缓存 | 热点数据是否缓存、缓存命中率 | Redis CLI / memcached-stats |
| 代码 | 循环内 IO、不必要的拷贝 | cProfile / Chrome DevTools |
| 网络 | 请求合并、gzip、CDN | Lighthouse / WebPageTest |
| 内存 | 内存泄漏、大对象未释放 | memory_profiler / valgrind |

## 必选章节
- 质量评估报告（5维 × 4级评分）
- 代码审查结果（按清单逐项 Pass/Fail）
- 重构建议（按优先级排序）
- 测试策略与覆盖率目标
- 性能优化建议（含度量基线）

## Gate 规则
- 质量评估须覆盖 5 个维度，每维度有 L1-L4 评级
- 代码审查清单须逐项标注，不能遗漏
- 重构建议须按优先级排序，每项有具体代码位置
- 测试策略须含覆盖率目标，按代码类型分层
- 性能优化须有度量基线，不能只说"需要优化"
