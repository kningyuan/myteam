# 调试方法论

## 任务描述
系统化定位并修复代码缺陷，要求根因可追溯、修复可验证、回归有防护，避免"改了能跑但不知道为什么"的盲目修复。

## 调试流程

### 1. 复现与隔离
- **稳定复现** — 找到 100% 复现的条件序列（输入/状态/时序）
- **最小复现场景** — 逐步删减无关因素，找到最小触发路径
- **环境快照** — 记录复现时的环境（OS/依赖版本/配置/数据状态）

### 2. 根因定位

| 手法 | 适用场景 | 操作 |
|------|----------|------|
| **二分法** | 大范围不确定 | 注释一半代码，看 bug 是否消失，逐步缩小 |
| **日志追踪** | 运行时状态相关 | 在关键路径加日志，追踪数据流 |
| **断点调试** | 可交互环境 | 条件断点 + 变量监控 |
| **差异对比** | 回归型 bug | git diff 对比正常版本与异常版本 |
| **压力测试** | 并发/性能相关 | 逐步加压，观察临界点 |

### 3. 根因分析
- **5 Why 追问** — 连续追问"为什么"，直到找到根本原因
- **区分症状与病因** — 崩溃是症状，空指针是病因，未初始化是根因
- **分类归档**：
  - 逻辑错误（条件判断/边界/状态机）
  - 并发问题（竞态/死锁/可见性）
  - 资源泄漏（内存/文件/连接）
  - 环境依赖（版本/配置/路径）
  - 数据问题（脏数据/格式/编码）

### 4. 修复与验证
- **最小修复** — 只改必要的代码，不顺手重构
- **修复验证** — 用最小复现场景验证修复有效
- **回归测试** — 确保修复未引入新问题
- **边界测试** — 测试修复的边界条件（空值/极值/并发）

### 5. 防护与沉淀
- **添加测试** — 为 bug 写回归测试，确保不再复现
- **添加防御** — 在入口处加校验/断言，防止同类问题
- **记录教训** — 写入 KB（根因/修复方案/防护措施）

## 常见反模式

| 反模式 | 问题 | 正确做法 |
|--------|------|----------|
| 随机改代码试 | 浪费时间，可能引入新bug | 先复现，再定位 |
| 只改症状不治本 | bug会以其他形式重现 | 5Why追根因 |
| 修复后不加测试 | 同类bug会回归 | 写回归测试 |
| 修复时顺手重构 | 扩大变更范围，增加风险 | 最小修复，重构另行 |
| 不记录调试过程 | 同类问题重复排查 | 沉淀到KB |

## 必选章节
- 复现条件（含环境与步骤）
- 根因分析（5 Why 追问链）
- 修复方案（最小变更）
- 验证结果（含回归测试）
- 防护措施（测试/防御代码/KB条目）

## Gate 规则
- 须有稳定复现条件，不能写"偶发"
- 根因须有 5 Why 追问链
- 修复方案须标注具体代码位置和变更行数
- 须有回归测试验证
