# DevOps与CI/CD方法论

> **最佳实践来源**：精通CI/CD 2025年最新生产环境实践，DevOps可观测性vs监控

## 何时启用

- `task_type` 为 `code-deployment`、`code-deliverable`
- 用户要求"部署""CI/CD""DevOps""监控""SRE"

## 核心实践

### 1. GitOps 部署标准

| 原则 | 实践 |
|------|------|
| Git 为唯一可信来源 | 所有环境变更通过 Git 提交 |
| 声明式配置 | 环境状态用 YAML/HCL 描述 |
| 自动同步 | ArgoCD/Flux 自动拉取并同步 |
| 快速回滚 | git revert 即回滚 |

### 2. 渐进式交付

| 策略 | 适用场景 | 风险 |
|------|----------|------|
| 蓝绿部署 | 需要瞬时切换 | 资源翻倍 |
| 金丝雀发布 | 需要小流量验证 | 需流量路由 |
| 功能标志 | 需要发布与部署解耦 | 技术债务 |
| 滚动更新 | 无状态服务 | 需要健康检查 |

**多阶段环境**：dev → staging → prod，每阶段设独立验证规则，自动推进。

### 3. 全链路可观测性

**三支柱**：
- **Metrics（指标）**：Prometheus + Grafana，CPU/内存/QPS/延迟/错误率
- **Logs（日志）**：ELK/Loki，结构化日志，关联 trace ID
- **Traces（追踪）**：Jaeger/Tempo，请求链路全貌

**告警原则**：
- 告警须可执行（收到告警知道做什么）
- 告警须有优先级（P0/P1/P2）
- 避免告警风暴（聚合+抑制+静默）
- 告警≠监控：监控告诉你"什么坏了"，可观测性告诉你"为什么坏"

### 4. 安全左移（DevSecOps）

| 阶段 | 安全实践 |
|------|----------|
| 需求 | 定义安全验收用例 |
| 开发 | SAST 静态扫描、依赖漏洞扫描 |
| 测试 | DAST 动态扫描、容器漏洞扫描 |
| 部署 | 密钥管理（Vault）、合规即代码 |
| 运行 | 供应链安全、许可证合规 |

### 5. 度量驱动改进

**DORA 四指标**：

| 指标 | 精英标准 |
|------|----------|
| 部署频率 | 每日多次 |
| 变更前置时间 | <1 小时 |
| 平均恢复时间（MTTR） | <10 分钟 |
| 变更失败率 | <15% |

**工具链收敛**：3±1 个工具，减少上下文切换。

## CI/CD Pipeline 标准阶段

```
代码提交 → Lint/类型检查 → 单元测试 → 构建 → 安全扫描 → 集成测试 → 部署staging → E2E测试 → 金丝雀部署 → 全量部署
```

**每个阶段的门禁**：
- Lint 失败 → 阻断
- 单元测试覆盖率 <80% → 阻断
- 安全扫描有 Critical → 阻断
- E2E 测试失败 → 阻断
- 金丝雀错误率 >1% → 自动回滚

## 质量红线

- 禁止手动部署到生产 — 须通过 CI/CD
- 禁止无回滚方案的部署 — 须含回滚步骤
- 禁止无监控的上线 — 须含健康检查+告警
- 禁止硬编码密钥 — 须用 Vault/Secret Manager

## Gate 检查清单

- [ ] 部署方案含 GitOps 流程
- [ ] 含渐进式交付策略（蓝绿/金丝雀/滚动）
- [ ] 含回滚预案（触发条件+步骤+验证）
- [ ] 含监控告警方案（指标+阈值+通知渠道）
- [ ] 含安全扫描（SAST/DAST/依赖扫描）
- [ ] 含 DORA 指标基线
