# 产品发现与验证 — SKILL

本 Skill 指导 Agent 在产品调研、需求分析任务中运用发现式方法，避免"拍脑袋"式规划。

## 核心流程

### 1. 问题空间探索
- **用户访谈要点**：问"为什么"而非"要什么"
- **痛点验证**：用户说的问题是真痛点还是伪需求
- **场景还原**：让用户描述最近一次遇到该问题的完整场景
- **频率与强度**：问题发生的频率和影响程度

### 2. 假设清单
将产品想法转化为可验证的假设：
```
我们相信 [用户群体] 在 [场景] 下 遇到 [问题]，
如果提供 [解决方案]，他们将 [预期行为]，
我们可以通过 [指标] 验证。
```

### 3. MVP 定义
- MVP 不是"功能删减版"，是"最小可验证单元"
- 一个 MVP 只验证一个核心假设
- 砍掉所有不服务于核心假设的功能
- 定义可衡量的成功标准（不是"用户满意"，而是"X% 用户在 Y 天内完成 Z"）

### 4. 假设测试方法
| 假设类型 | 测试方法 | 周期 |
|---------|---------|------|
| 用户有这个问题吗 | 用户访谈（5-8 人） | 1-2 周 |
| 解决方案可行吗 | 原型测试 | 1-2 周 |
| 用户会用吗 | 着陆页测试 / 烟雾测试 | 1 周 |
| 用户愿意付费吗 | 预售 / 意向金 | 1-2 周 |

### 5. 迭代验证
- 每轮迭代后更新假设清单（验证/推翻/新增）
- 记录学习日志：我们学到了什么、下一步验证什么
- 不执着于初始方案，让数据驱动方向调整

## 红线

- 禁止在没有用户访谈的情况下定义需求
- 禁止把"竞品有"作为做功能的理由
- 禁止用"用户满意度"等不可衡量指标作为成功标准
- 禁止一个 MVP 验证多个假设

## 交付物

- 问题假设清单（含验证状态）
- MVP 定义文档（核心假设 + 成功标准 + 功能边界）
- 用户访谈纪要（场景 + 痛点 + 频率）
- 迭代学习日志
