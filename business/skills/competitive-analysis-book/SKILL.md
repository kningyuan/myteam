# 竞品分析方法论（专业书转化）

> 来源：《竞品分析方法论：从入门到精通》（6 章节框架）
> 转化方式：book-to-skill 提取结构，非摘要

## 核心心智模型

竞品分析 = **目标驱动 → 维度框架 → 信息采集 → 洞察提炼 → 策略建议**

五个环节缺一不可，且必须按序执行。常见错误：跳过"目标"直接做"对比"，导致分析没有方向。

## 何时启用

- `task_type` 为 `competitive-analysis`、`research`
- 用户要求"竞品分析""竞品对比""市场分析"

## 六章节核心框架

### 第一章：竞品分析基础

**三个目标类型**（决定分析方向）：
1. **决策支持** — 是否进入新市场？如何定位？→ 输出：定位建议+竞争策略
2. **学习借鉴** — 对手做对了什么？可复制什么？→ 输出：最佳实践清单
3. **市场预警** — 行业格局变化？新威胁出现？→ 输出：风险预警报告

**三类竞品**：
- 直接竞品（功能定位相似）
- 间接竞品（形态不同但解决相同需求）
- 替代品（完全不同方案但满足相同场景）

### 第二章：竞品选择与维度确定

**选品标准**：3-4 款为宜，不超过 5 款；三类竞品都要覆盖。

**按角色选维度**：
| 角色 | 维度 |
|------|------|
| 产品 | 用户体验五层 + 业务流程 |
| 运营 | 获客渠道、商业模式、运营策略 |
| 技术 | 技术架构、性能、安全 |
| 通用 | 公司背景、团队、资金、数据、营收 |

**用户体验五层框架**（产品视角必备）：
1. 战略层 — 产品定位、目标用户、核心价值主张
2. 范围层 — 功能规格、内容需求
3. 结构层 — 交互设计、信息架构
4. 框架层 — 界面设计、导航设计、信息设计
5. 表现层 — 视觉设计

### 第三章：信息收集方法

**信息源优先级**（从高到低）：
1. 一手来源 — 官网、文档、定价页、博客
2. 用户评价 — 应用商店、社区论坛、社交媒体
3. 第三方评测 — G2、Capterra、TrustRadius、行业报告
4. 公开数据 — 融资信息、用户规模、市场份额

**采集要求**：
- 每条信息标注 URL + 采集时间 + 可信度（高/中/低）
- 信息缺口明确列出，不编造
- 交叉验证：关键数据至少两个独立来源确认

**可信度评估**：
| 可信度 | 来源类型 | 示例 |
|--------|----------|------|
| 高 | 一手官方 | 官网定价页 |
| 中 | 权威第三方 | G2 评测 |
| 低 | 用户主观 | 社交媒体评论 |

### 第四章：数据分析与洞察提炼

**三大分析工具**：
1. **对比矩阵** — 行=竞品，列=维度，格子=数据+来源
2. **SWOT** — 优势/劣势/机会/威胁
3. **洞察提炼** — 每个发现须有数据支撑 + 差异化判断 + 战略含义

**洞察 ≠ 罗列**：
- ❌ 罗列：Cursor 支持 Agent，Windsurf 也支持 Agent
- ✅ 洞察：Cursor 的 Agent 强调自主性（数周运行），Windsurf 强调多 Agent 协作管理

### 第五章：策略建议与报告

**关键发现格式**：
```
### 关键发现 N：[一句话标题]
- 优先级：P0/P1/P2
- 依据：[具体数据] [来源N]
- 洞察：[差异化判断]
```

**策略建议要求**：
- 可执行（指明做什么、怎么做）
- 含优先级（P0 立即做 / P1 短期做 / P2 长期做）
- 含依据（关联到关键发现）

**信息缺口透明化**：列出哪些数据查不到 + 说明对结论的影响。

### 第六章：交付物质量标准

**结构完整性**：四章节齐全 + 对比矩阵（≥3×3）+ 来源表
**数据可信度**：每个量化数据有来源 + 信息缺口明确
**洞察深度**：对比表有"分析洞察"列 + 关键发现 ≥3 条

## 速查表

| 场景 | 用什么 |
|------|--------|
| 选竞品 | 3-4 款，含三类 |
| 定维度 | 按角色选（产品/运营/技术） |
| 找来源 | 一手 > 用户评价 > 第三方 > 公开数据 |
| 建矩阵 | 行=竞品，列=维度 |
| 写发现 | 标题+优先级+依据+洞察 |
| 给建议 | 可执行+优先级+依据 |
| 缺数据 | 明确列出，不掩盖 |

## 反模式

- ❌ 跳过"目标"直接做"对比" — 分析没有方向
- ❌ 只罗列不分析 — 对比表没有"分析洞察"列
- ❌ 编造数据 — 须标注来源
- ❌ 掩盖数据缺失 — 须列信息缺口
- ❌ 无建议的结论 — 须含 P0/P1 优先级 + 可执行建议
