# 方案撰写方法论

## 任务描述
撰写高质量方案文档（产品方案/技术方案/运营方案/商业方案），要求结构清晰、论据充分、可执行可验证，避免空话套话。

## 方案结构（黄金七段式）

### 1. 背景与上下文
- **行业/市场背景** — 用数据说话，标注来源（报告名+年份+页码）
- **内部现状** — 当前能力盘点、痛点描述、已有尝试及结果
- **触发事件** — 为什么现在要做这件事（时间窗口/竞争压力/用户需求）
- **篇幅控制** — 不超过全文 15%

### 2. 问题定义
- **问题陈述** — 一句话说清楚要解决什么问题
- **影响范围** — 受影响的用户/业务/系统
- **量化痛点** — 用数据描述问题的严重性（损失金额/流失率/效率损耗）
- **根因分析** — 5 Why 追问法，找到根本原因而非表面现象

### 3. 方案设计
- **设计原则** — 3-5 条不可妥协的原则（如：先有后优、数据驱动、最小侵入）
- **整体架构** — 用图说明（架构图/流程图/模块图），不用纯文字描述系统结构
- **核心机制** — 关键设计决策及其理由（为什么选 A 不选 B）
- **替代方案对比** — 至少列 2 个备选方案，用对比表说明取舍

|------|-------|-------|-------|
| 实现复杂度 | | | |

| 风险 | | | |

### 4. 实施路径
- **阶段划分** — 按 MVP → V1 → V2 分期，每期有明确交付物
- **任务拆解** — WBS（工作分解结构），每项任务 ≤3 人天
- **里程碑** — 关键节点与验收标准
- **资源需求** — 人力/服务器/第三方服务/预算
- **依赖关系** — 内部依赖 + 外部依赖 + 阻塞项

### 5. 预期效果
- **量化目标** — SMART 原则（具体/可度量/可达成/相关/有时限）
- **成功标准** — 什么算成功（达标线 vs 超预期线）
- **衡量方式** — 怎么测量（埋点/报表/用户调研）
- **时间预期** — 效果显现周期（短期1月/中期3月/长期6月+）

### 7. 附录
- 术语表
- 参考资料（报告/文章/竞品分析）
- 详细数据表
- 技术细节（API 文档/数据库设计）

## 写作原则

1. **结论先行** — 每个章节第一句话就是核心结论，后面是支撑论据
2. **数据说话** — 每个判断都要有数据支撑，标明来源
3. **图文并茂** — 关键架构/流程/对比用图表呈现，不用纯文字
4. **可执行性** — 方案读完就能知道"下一步做什么"
5. **可验证性** — 每个目标都有对应的验收标准
6. **分级呈现** — 摘要（1页）→ 详案（10-20页）→ 附录（不限）

## 禁止清单
- 禁止"有潜力""建议完善""逐步优化"等空话
- 禁止无数据支撑的判断（"用户可能需要""市场应该很大"）
- 禁止只给方案不给替代方案对比
- 禁止无风险分析的实施计划
- 禁止无验收标准的预期效果

## 必选章节
- 背景与上下文（含量化数据）
- 问题定义（含根因分析）
- 方案设计（含替代方案对比表）
- 实施路径（含 WBS 拆解）
- 预期效果（含 SMART 目标）
- 风险评估（含应对策略）

## Gate 规则
- 背景数据须标注来源，不能只写"据调研"
- 方案设计须含至少 2 个替代方案对比
- 实施路径须含 WBS 拆解，每项 ≤3 人天
- 预期效果须为 SMART 目标，不可模糊
- 风险评估须含概率+影响+应对策略三要素
