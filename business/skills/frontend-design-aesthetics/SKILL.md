# 前端设计与审美方法论

## 任务描述
产出具有专业审美水准的前端界面设计方案，避免"紫色渐变+Inter字体"的AI生成同质化风格，建立可复用的设计规范。

## 核心原则

### 1. 视觉层次（Visual Hierarchy）
- **对比优先**：通过大小（≥1.5x差异）、颜色（明暗对比≥3:1）、间距（8px网格倍数）建立层次
- **F型/Z型阅读路径**：关键信息沿阅读路径放置
- **留白即设计**：内容区与留白比例不低于 3:1，避免信息过载

### 2. 色彩理论
- **主色+辅色+强调色**：60-30-10 分配法则
- **禁止默认AI配色**：避免 `from-purple-500 to-pink-500`、`bg-slate-900` 等 Tailwind 默认渐变
- **色板生成**：使用 OKLCH 色彩空间，确保感知均匀
- **暗色模式**：背景 #0F0F0F 而非 #000000，文字 #E5E5E5 而非 #FFFFFF，降低对比疲劳

### 3. 排版规则
- **字体选择**：中英文搭配（思源黑体 / Noto Sans CJK SC + Inter / IBM Plex Sans），避免单一 Inter
- **字号阶梯**：12 / 14 / 16 / 20 / 24 / 32 / 48 / 64 px，不使用中间值
- **行高**：正文 1.6-1.8，标题 1.2-1.4
- **字重**：正文 400，强调 500-600，标题 700+，避免全 400

### 4. 组件设计
- **圆角统一**：小元素 8px，卡片 12px，大容器 16px，不用 `rounded-full` 做卡片
- **阴影层次**：3级阴影体系（hover/active/float），不用 `shadow-2xl` 一把梭
- **过渡动画**：150-300ms ease-out，避免弹跳动画（`bounce`）
- **图标系统**：统一线性/面性风格，不混用，尺寸 16/20/24px

## 反AI审美清单

以下模式**禁止使用**（AI生成代码的典型同质化标志）：

| 反模式 | 替代方案 |
|--------|----------|
| `bg-gradient-to-r from-purple-500 to-pink-500` | 使用品牌色或低饱和度配色 |
| 全场 `rounded-2xl` | 按层级使用不同圆角 |
| `backdrop-blur-xl bg-white/10` | 实色背景 + 细微边框 |
| `text-transparent bg-clip-text` 渐变文字 | 实色 + 字重区分 |
| `animate-pulse` / `animate-bounce` | 微妙的 opacity 或 transform 过渡 |
| `grid grid-cols-3 gap-8` 三等分卡片 | 不对称布局或 bento grid |
| 默认 Inter 字体 | 搭配中文字体或选择有性格的英文字体 |

## 设计流程

1. **理解品牌** — 提取品牌关键词、目标用户、行业属性
2. **建立色板** — 主色/辅色/强调色/中性色/语义色，输出 CSS 变量
3. **排版系统** — 字体搭配 + 字号阶梯 + 行高规范
4. **组件库** — 按钮/卡片/表单/导航/弹窗的统一规范
5. **页面布局** — 网格系统 + 间距系统 + 响应式断点
6. **微交互** — hover/active/loading/error 状态定义
7. **设计走查** — 对照反AI审美清单逐条检查

## 必选章节
- 设计理念与品牌关键词
- 色彩规范（含 CSS 变量定义）
- 排版规范（字体/字号/行高）
- 组件设计规范（至少 5 个核心组件）
- 反AI审美走查清单（逐条 Pass/Fail）

## 工具推荐
- Figma — 设计稿与组件库
- Tailwind CSS — 原子化样式（但需自定义配色）
- Radix UI / shadcn/ui — 无样式可定制组件
- Coolors / OKLCH Color Picker — 色板生成

## Gate 规则
- 色板须有 CSS 变量定义，不能只写 Tailwind 类名
- 组件规范须包含至少 3 种状态（default/hover/disabled）
- 反AI审美清单须逐条标注，不能遗漏
- 中文字体须显式声明，不能依赖系统默认
