# 工程最佳实践 — SKILL

本 Skill 汇总软件工程最佳实践，指导 Agent 在编码、交付、测试任务中保持工程质量。

## 核心原则

### 1. 最小 diff 原则
- 只改动任务要求的代码，不顺手重构无关代码
- 不删除既有死代码（除非任务明确要求）
- 匹配现有代码风格（缩进、命名、注释语言）
- 新增代码量与任务复杂度成正比

### 2. SOLID 原则
- **单一职责**：一个函数/类只做一件事
- **开闭原则**：对扩展开放，对修改关闭
- **里氏替换**：子类必须能替换父类
- **接口隔离**：不强制依赖不需要的接口
- **依赖倒置**：依赖抽象而非具体实现

### 3. 测试金字塔
```
        /\
       /E2E\        ← 少量（关键路径）
      /------\
     / 集成测试 \    ← 适量（模块间契约）
    /----------\
   /  单元测试   \   ← 大量（核心逻辑）
  /--------------\
```
- 单元测试覆盖核心业务逻辑
- 集成测试验证模块间契约
- E2E 测试只覆盖关键用户路径
- 测试必须可复现、可独立运行

### 4. 契约优先
- 改动前先理解现有契约（函数签名、API 接口、数据模型）
- 破坏性改动须先更新契约定义，再改实现
- 跨模块改动须确认上下游影响

## 红线

- 禁止引入未经允许的外部依赖
- 禁止提交无法通过编译/语法检查的代码
- 禁止跳过测试直接交付
- 禁止用 try-catch 吞掉异常而不记录
- 禁止硬编码环境特定配置（路径、密钥、端口）

## 交付前检查清单

- [ ] 代码可通过编译/语法检查
- [ ] 新增逻辑有对应测试
- [ ] 测试全部通过
- [ ] 无 console.log / print 调试残留
- [ ] 无硬编码配置
- [ ] diff 只包含任务相关改动
