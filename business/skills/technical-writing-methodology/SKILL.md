# 技术写作方法论

## 任务描述
撰写技术文档（API文档/架构文档/用户手册/运维手册），要求结构清晰、语言准确、可操作可维护。

## 文档类型与结构

### 1. API 文档
```
概述 → 认证 → 错误码 → 接口列表（请求/响应/示例）→ 变更日志
```

### 2. 架构文档
```
背景与目标 → 整体架构图 → 模块说明 → 数据流 → 部署架构 → 技术选型理由 → 演进规划
```

### 3. 用户手册
```
快速入门 → 核心功能操作（步骤+截图）→ 配置说明 → 常见问题 → 最佳实践
```

### 4. 运维手册
```
环境要求 → 部署步骤 → 配置项说明 → 监控告警 → 故障排查 → 应急预案 → 回滚流程
```

## 写作规范

### 语言风格
- **简洁直述**：一句话一个意思，避免长句嵌套
- **主动语态**："系统发送通知"而非"通知被系统发送"
- **术语一致**：同一概念全文用同一词，不混用（如"用户"和"会员"不同时出现）
- **祈使句**：操作步骤用祈使句（"点击保存"而非"您需要点击保存"）

### 格式规范
- **标题层级**：H1(标题) → H2(章节) → H3(小节)，不跳级
- **代码块**：标注语言（```python），含注释
- **表格**：用于对比/参数说明，不用列表替代
- **图表**：架构图/流程图/时序图，用 Mermaid 或图片
- **链接**：内部链接用相对路径，外部链接标明来源

### 数量约束
- 每页不超过 300 行
- 每段不超过 5 行
- 每句不超过 40 字（中文）
- 列表项不超过 1 行

## 质量检查清单

| 检查项 | Pass/Fail |
|--------|-----------|
| 标题层级是否连续不跳级 | |
| 术语是否全文一致 | |
| 代码示例是否可运行 | |
| 操作步骤是否有预期结果 | |
| 截图是否标注操作位置 | |
| 是否有变更日志 | |
| 是否有目录/导航 | |

## 必选章节
- 文档概述与目标读者
- 目录结构
- 正文内容（按文档类型结构）
- 变更日志
- 质量检查清单

## Gate 规则
- 须有目录结构，不能直接堆砌正文
- 代码示例须标注语言并可运行
- 操作步骤须有"预期结果"
- 术语须全文一致，无混用
