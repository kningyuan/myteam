## Product Research Execute Flow

### Procedure

1. **明确调研范围**：确定赛道（如 AI Agent 工具链）、研究对象、成功指标、非目标
2. **数据采集**：通过 websearch 获取 Gartner/McKinsey 等权威机构数据，采集 GitHub/Discord/Reddit 二手用户反馈
3. **结构化交付**：
   - 调研目标（scope + success metrics + non-goals）
   - 市场概况（TAM/SAM/SOM + CAGR + 数据来源）
   - 竞品分析（对比矩阵 + 各自定位）
   - 用户洞察（痛点分级 P0-P2 + 证据来源）
   - 机会与建议（产品方向 + 架构图 + 验证路径 + 不确定性声明）
4. **质量自检**：数据是否引用来源、痛点是否有证据支撑、机会是否可验证

### Pitfalls

- 市场规模数据综合估算而非精确统计 → 必须在 known_gaps 中声明
- 竞品分析停留在功能对比 → 应标注各自定位差异
- 用户痛点仅来自二手数据 → 需说明数据局限性
- deliverable 缺少不确定性声明 → 需覆盖技术/市场/竞争三维度风险

### Verification

- [ ] 调研目标包含 scope + success metrics + non-goals
- [ ] 市场数据标注来源（Gartner/McKinsey/IDC 等）
- [ ] 竞品矩阵至少覆盖 3 个竞品
- [ ] 用户痛点分级（P0/P1/P2）并标注证据来源
- [ ] 机会建议附带验证路径
- [ ] 不确定性声明覆盖技术/市场/竞争三维度
