## Procedure

### Step 1: Project Context Assessment
1. Check if project directory exists and contains files
2. Review any existing documentation or code
3. Identify available resources and constraints

### Step 2: Requirement Clarification
1. For ambiguous requests, ask specific questions
2. Define clear research objectives
3. Establish success criteria

### Step 3: Research Execution
1. Follow the four-section deliverable structure
2. Document all information sources
3. Include both findings and limitations

### Step 4: Quality Review
1. Self-assess conservatively
2. Document known gaps
3. Ensure all sections are complete

## Pitfalls

### 1. Empty Project Directory
**Problem**: Starting research on an empty project without acknowledging the limitation.
**Solution**: 
- Check project structure first
- Document the limitation in the deliverable
- Focus on general recommendations when specific analysis is impossible

### 2. Vague Requirements
**Problem**: Interpreting '做点事' without clarification.
**Solution**:
- Ask for specific requirements
- Provide multiple options for the user to choose from
- Document assumptions made

### 3. Quality Overconfidence
**Problem**: Self-assessing quality too high (e.g., 0.85 when actual is 0.0).
**Solution**:
- Be conservative in self-assessment
- Document all limitations
- Let results speak for themselves

## Verification

### Quality Checklist
- [ ] Project context assessed
- [ ] Requirements clarified
- [ ] Four-section structure followed
- [ ] Information sources documented
- [ ] Known gaps identified
- [ ] Conservative self-assessment

### Success Criteria
1. Deliverable follows the four-section structure
2. All assumptions are documented
3. Limitations are clearly stated
4. Recommendations are actionable
