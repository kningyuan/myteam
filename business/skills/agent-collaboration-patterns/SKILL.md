# 多 Agent 协作模式 — SKILL

本 Skill 指导 coordinator（main agent）在团队协作项目中如何分解任务、编排 Agent、设置闸门。

## 编排模式

### 1. 串行流水线（Pipeline）
```
Agent A → 交付物 → Agent B → 交付物 → Agent C
```
- 适用：后一步依赖前一步完整输出
- 示例：调研 → 规划 → 开发
- 风险：任一环节卡住全链路阻塞

### 2. 并行扇出（Fan-out）
```
       ┌→ Agent A →┐
Goal →→├→ Agent B →├→ 汇总
       └→ Agent C →┘
```
- 适用：子任务相互独立
- 示例：同时调研 3 个竞品
- 要求：汇总节点有合并策略

### 3. 循环迭代（Loop）
```
Agent A → 交付物 → Reviewer → 不通过 → 回到 A
                  ↓ 通过
                  完成
```
- 适用：质量不达标需反复打磨
- 示例：方案撰写 + 评审循环
- 要求：定义退出条件（max_cycles 或质量阈值）

### 4. 圆桌讨论（Roundtable）
```
Agent A ↗
Agent B → 主持人汇总
Agent C ↘
```
- 适用：需要多视角输入的决策
- 示例：架构方案评审（arch + developer + tester 各发表观点）

## 任务分解原则

1. **单一职责**：一个任务只分配给一个 Agent，只产出一个交付物
2. **契约明确**：任务间通过明确的交付物格式传递（非口头描述）
3. **可验证**：每个任务有可执行的验收标准（Gate 检查）
4. **粒度适中**：任务不要太小（开销大于产出）也不要太大（难以并行）

## Gate 闸门设计

| 闸门类型 | 检查内容 | 失败处理 |
|---------|---------|---------|
| 格式闸门 | 交付物是否符合契约格式 | 重新执行 |
| 完整性闸门 | 必需章节/字段是否齐全 | 重新执行 |
| 质量闸门 | 内容是否达到质量阈值 | 循环迭代 |
| 依赖闸门 | 前置任务是否已完成 | 等待 |

## 冲突处理

- **交付物冲突**：两个 Agent 修改同一文件 → coordinator 仲裁，后改者基于前者输出
- **意见冲突**：圆桌讨论意见不一致 → coordinator 决策，记录 ADR
- **资源冲突**：多任务争用同一 Agent → 排队或并行 workspace

## 红线

- 禁止跳过 Gate 直接进入下一阶段
- 禁止 coordinator 自己执行 worker 任务（职责分离）
- 禁止无 max_cycles 的死循环
- 禁止任务间传递非结构化信息（必须用契约模型）
