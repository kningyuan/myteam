# 完成前验证

> 来源：obra/superpowers (MIT)，适配 myteam。

## 铁律

```
没有新鲜验证证据，不声称完成
```

未经验证就声称完成，不是效率，是不诚实。

## 门控函数

```
声称任何状态或表达满意前：

1. 识别：什么命令能证明这个声称？
2. 运行：执行完整命令（新鲜的，完整的）
3. 阅读：完整输出，检查退出码，数失败数
4. 验证：输出是否确认声称？
   - 否→陈述实际状态+证据
   - 是→陈述声称+证据
5. 然后才能：做出声称

跳过任何步骤 = 撒谎
```

## 常见声称的验证要求

| 声称 | 需要 | 不充分 |
|------|------|--------|
| 测试通过 | 测试命令输出：0 失败 | 上次运行、"应该通过" |
| Lint 干净 | Lint 输出：0 错误 | 部分检查、外推 |
| 构建成功 | 构建命令：exit 0 | Lint 通过、日志看起来好 |
| Bug 已修 | 测试原始症状：通过 | 改了代码、假设修好了 |
| 需求满足 | 逐行清单核对 | 测试通过 |
| 任务完成 | VCS diff 显示变更 | Agent 报告"成功" |

## 红旗 — 看到就停

- 使用"应该""大概""看起来"
- 验证前表达满意（"完成！""搞定！"）
- 提交/推送/PR 前未验证
- 信任 agent 成功报告而不独立验证
- 依赖部分验证
- "就这一次"

## 关键模式

**测试：**
```
✅ [运行测试] [看到: 34/34 pass] "所有测试通过"
❌ "应该通过了" / "看起来正确"
```

**回归测试（TDD Red-Green）：**
```
✅ 写测试→运行(通过)→还原修复→运行(必须失败)→恢复→运行(通过)
❌ "我写了回归测试"（无 red-green 验证）
```

**需求：**
```
✅ 重读计划→创建清单→逐项验证→报告差距或完成
❌ "测试通过，阶段完成"
```

## myteam 红线
