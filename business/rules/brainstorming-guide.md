# 讨论与头脑风暴专规

头脑风暴与群组圆桌为同一类 **讨论模式**：只产出观点与方案，不跑项目任务执行流。

## 如何识别

满足以下 **任一** 即进入讨论模式（**本条优先于** 同上下文中的 `worker-template.md` 以及 workspace `AGENTS.md` 里与「任务执行」冲突的段落）：

- 私聊中用户征询意见、方案、可行性、评审
- 群组消息以 **`[群组圆桌`** 开头（立论轮、对齐轮、主持汇总）
- 群组 @mention 后直接讨论（如「@arch 帮我想想这个方案」）
- Workflow / 流程的 **设计、评审、选型**（尚未进入项目 execute 派活）

**不属于** 讨论模式：收到 **项目协作** 类 trigger（`.trigger/`、`phase=evaluate` / `phase=execute`）→ 改按 `worker-template.md` 执行。

## 禁止（讨论模式）

- 读取或检查 **`.trigger` / `.response`** 及 trigger 任务流
- `phase=evaluate` / `phase=execute` 与 JSON 响应模板
- 项目协作路径：`task-complete`、`deliverables/`、`project_data` 等
- **Write / Edit** 改文件、**Bash** 执行命令（含安装、部署、跑测试）

## 允许的工具（调研与阅读）

为支撑讨论，**可以且应当在需要时**使用只读/调研类工具：

- **WebSearch / WebFetch**：检索网络事实、政策、竞品、行业数据
- **Read / Grep / Glob**：阅读本地文档或代码以核实细节（勿改文件）
- **Think**（若 CLI 提供）：内部推理

工具过程会展示给用户；**最终回复**仍须结构化正文，不要把工具日志原样粘贴当答案。

## 输出要求

- 用中文，**结构化**（`##` 小标题 + 列表）
- 缺少事实依据时，先调研再发言
- 聚焦可执行的流程、分工、验收或 workflow **设计**建议
- 不要 JSON；群组圆桌中不要 @ 其他 Agent（UI 会展示身份）
- 只输出本轮讨论正文，不要步骤清单式的「先去检查某 trigger 目录」

### 圆桌主持汇总（若消息标明主持汇总）

输出结构建议：

- `## 已共识`
- `## 分歧点`
- `## 待用户拍板`
- `## 建议 workflow / 下一步`

最后一轮须含 `## 共识结论` 与 `## 仍存分歧（需用户拍板）`；未完全共识时另给 `## 保守方案`。

## 与项目任务执行的区别（速查）

| 维度 | 讨论 / 头脑风暴 / 圆桌 | 项目任务执行 |
|------|------------------------|--------------|
| 典型触发 | 私聊、群组 @、`[群组圆桌` | `.trigger/` + executor 派活 |
| 产出 | 对话中的结构化观点 | JSON → `.response/` + 交付物 |
| 专规文件 | 本文件 | `worker-template.md` |
